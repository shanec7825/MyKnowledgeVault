# 线性表

## 定义

**线性表：有限个元素组成的有序序列。**

拆开看，每个词都有约束：

- **有限**——元素个数是确定的整数 n（n ≥ 0，n = 0 是空表）。
- **有序**——元素之间有次序，第 i 个和第 i+1 个的位置不能互换。
- **序列**——同一个值可以出现多次，位置是元素的身份（不是值本身）。

逻辑关系只有一条规则：**除第一个元素外，每个元素有且仅有一个前驱；除最后一个元素外，每个元素有且仅有一个后继。** 这是「线性」的全部含义——它描述的是一对一的邻接关系，与内存怎么放无关。

## 逻辑结构 vs 物理实现

这是本概念最重要的一点，也是最容易被教材混着讲糊掉的一点。

| | 线性表（逻辑结构） | 顺序表 / 链表（物理实现） |
| --- | --- | --- |
| 回答的问题 | 元素之间是什么关系？ | 元素在内存里怎么放？ |
| 内容 | 前驱后继、有限序列 | 连续内存 + 下标，或结点 + 指针 |
| 与操作的关系 | 决定**能做什么** | 决定**做得多快** |

同一个线性表，两种物理实现：顺序存储（顺序表 / 动态数组）与链式存储（链表）。它们**逻辑上完全等价**——同一组操作契约，同一组语义；差异全部在效率、内存开销、失效行为上。

推论：栈、队列、串都是**受限的线性表**（限制操作发生的位置），它们的底层可以是顺序表也可以是链表。这就是为什么线性表是后续几乎所有结构的基础。

## ADT List 的操作契约

ADT（抽象数据类型）只定义「能做什么」，不定义「怎么存」。契约必须先于实现确定，否则实现和测试都无从判定对错。

| 操作 | 含义 | 约定 |
| --- | --- | --- |
| `init()` | 初始化空表 | 表长为 0 |
| `size()` | 返回元素个数 | 非负 |
| `empty()` | 是否为空 | true / false |
| `get(i)` | 取第 i 个元素 | i 越界则报错 |
| `set(i, e)` | 修改第 i 个元素 | i 越界则报错 |
| `insert(i, e)` | 在第 i 个位置插入 e | 0 ≤ i ≤ size；表长 +1 |
| `remove(i)` | 删除第 i 个元素并返回 | 0 ≤ i < size；表长 −1 |
| `append(e)` | 尾部追加 | 等价于 `insert(size, e)` |
| `search(e)` | 查找 e 的位置 | 找不到返回 −1 |
| `traverse()` | 遍历所有元素 | 按顺序访问 |

**三个必须显式约定的点**（不约定就会在写代码时翻车）：

1. **位置语义**——教材常用 1-based，代码常用 0-based。必须选定一种并在整个项目里统一。本工作区统一 **0-based**。
2. **是否允许重复**——允许。`search` 返回**第一个**匹配位置。
3. **越界行为**——抛异常 / 返回错误码 / 断言，三选一并保持一致。本工作区统一**抛 `std::out_of_range`**。

注意 `insert` 与 `get/set/remove` 的合法区间不同：`insert` 允许 `i == size`（尾部插入），其余不允许。这是最常见的边界错误来源。
