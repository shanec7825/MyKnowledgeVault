# 前沿内容的分层阅读法

**核心问题**：基础、数学、全局视角都不够的时候，怎么读前沿才不是白读？

**一句话结论**：读前沿不需要「先补齐基础」；需要的是**分层降级**——把「看不懂就放弃」换成「降一级再看」，并严格按「和自己的相关度」分配阅读深度。

## 概述

「基础不够所以读不懂前沿」这个前提本身就是错的。前沿内容其实是两类东西，混在一起才痛苦：

- **A 类 · 能力型前沿**：新模型架构、新训练方法、新系统优化。这类**确实需要基础**，基础不够读原文就是浪费生命。
- **B 类 · 方向型前沿**：这个领域在关心什么问题、大家在往哪走、什么被证伪了。这类**不需要基础**，只需要有人给你翻译。

大部分人的痛苦来自：拿着 B 类的需求（想知道发生了什么），去读 A 类的材料（论文原文）。于是每读一篇都挫败一次，最后得出「我基础太差」的结论。

正确的动作是**先分类，再决定读多深**。分类的成本是 30 秒，省下的是几个晚上。

## 核心内容

### 三层阅读深度

三层的划分标准不是「论文的重要性」，而是**「这篇和你的方向有多相关」**。一篇 Nature 封面文章如果和你无关，就只配 L1。

| 层         | 频率        | 读什么                                      | 产出（可判定）                       | 门槛  |
| --------- | --------- | ---------------------------------------- | ----------------------------- | --- |
| **L1 扫描** | 每天 15 分钟  | 标题 + 摘要 + 一两条评论                          | 一句话：谁做了什么                     | 零   |
| **L2 理解** | 每周 1 篇    | **先读别人的解读**（博客 / 视频 / 中文综述），再回头看原文的引言与结论 | 200 字用自己的话：它解决什么问题、替代了什么、局限在哪 | 低   |
| **L3 复现** | 每学期 1–2 个 | 原文逐行 + 代码                                | 跑通的代码 + 踩坑记录                  | 高   |

关键纪律：

- **L2 必须跳过所有数学推导**。你只需要回答「输入是什么、输出是什么、替代了谁」。
- **只有 L3 才允许补数学**。因为只有 L3 需要你真的理解机制。
- **L1 是地图，不是知识**。它的价值在于让你不被方向性变化甩下，不产生任何资本——不要自我感动。

> 同一篇论文内部的深度递进（三遍读法）见 [[wiki/CS本科学习手册|CS本科学习手册]] 4.1。本页讲的是**跨论文的选择**：哪些只扫、哪些精读、哪些复现。两者是正交的。

### 降级规则：读不懂时怎么办

不要「硬扛」也不要「放弃」，而是**降一级**。遇到任何一段读不懂的内容，依次问：

1. **我能说清它解决什么问题吗？** 不能 → 降级去看解读（博客 / 视频 / 中文综述），别碰原文。
2. **我需要它的方法细节吗？**（和我的方向相关吗）不需要 → **停在 L2**，别往下。
3. **我需要复现吗？** 需要 → 才进 L3，此时才去补数学。

反面例子：为了读懂一篇 attention 论文，先去啃完线性代数教材。三个月后论文早忘了，数学也忘了一半。**顺序反了。**

### 数学不够：按需补，不预补

数学是**按需补**，补到「够理解这一段论证」为止。具体动作：

- 读到一个不懂的公式 → 先判断它是**结论的装饰**还是**结论的核心**。
- 装饰 → 跳过。核心 → 去查**这一个概念**（不是整章、不是整本书）。
- 例：读 attention 遇到 softmax，你只需要知道「它把一组分数变成概率分布」，**不需要**会推导它的梯度。
- 判断标准：**能不能用自己的话说出这个公式在干什么**。能，就够用了。

数学能力是在「用」的过程中长出来的，不是在「学」的过程中攒够的。这个顺序对反馈驱动型学习者尤其重要。

### 全局视角：靠画图，不靠读综述

全局视角不是「读完所有东西」换来的，是**画图**换来的。读十篇综述不如自己画一遍。

做法：给一个领域画一条「问题演变线」，每个节点只写两件事——**上一个方案卡在哪 → 这个怎么解决的**。

以 LLM 主线为例（这就是一张可以直接抄的结构）：

| 阶段 | 解决了什么 | 卡在哪 |
| --- | --- | --- |
| n-gram | 用统计预测下一个词 | 只能看几个词，长距离依赖全丢 |
| RNN / LSTM | 能记住更长的上下文 | 串行计算慢，长程梯度仍不稳 |
| Attention / Transformer | 并行 + 任意距离直接连接 | 计算量 O(n²)，上下文越长越贵 |
| 预训练 + 微调（BERT / GPT） | 不用每个任务从头训 | 与人类偏好不对齐 |
| RLHF | 用人类反馈对齐偏好 | 依赖昂贵的人工标注 |
| Agent | 能调工具、多步执行任务 | 可靠性差，错误会级联 |

**这张图自己画一遍，比读十篇综述有用。** 画完你会发现：所谓「前沿」几乎都是「上一个方案的短板补丁」，而不是从天而降的新东西。这就是全局视角。

图适合放 `Excalidraw/`，说明文字写成概念页。

### 把日报改造成过滤器

`informationFinding` 工作台已经解决了「在哪拉」，但目前产出的是**噪音**：一天 97 条、全英文截断摘要、评分挤在 53–67 之间、方向全是 agent/memory/RL——对一个还在读 minGPT 的人，这些条目**读起来是天书，不读又焦虑**。

三个具体改动（对应项目页待办「评分权重按实际使用体验调校一轮」）：

1. **启用 LLM 中文摘要**：日报里写着「AI 摘要：未启用」，在 `.env` 配 `LLM_API_KEY` 后跑 `--ai`。这一步直接把「英文截断摘要」变成「中文一句话讲清它干了什么」——L1 扫描的效率取决于这一句。
2. **强制输出「今日必读 3 条」**：从 97 条里硬选 3 条，其余折叠。这个「强制选择」的约束会倒逼评分体系变准，比调权重参数有效得多。
3. **让「领域相关性」权重压过「社会热度」**：现在 `headcount`（日增 507 stars）这类热度货能排到第 3，说明热度权重过高。你的方向是从零实现与大模型基础，应把「与 LLM 原理/实现相关」的权重提上去。

改完之后，日报的定位从「信息推送」变成「**过滤器**」——它的职责是替你砍掉 95%，而不是让你看完 100%。

### 不建议作为学习源

X / Twitter 只用于**发现**（关注几个核心研究者，看到什么被反复转发），不用于学习。搬运视频同理——它们的价值是「让你知道有这个东西」，看完不会留下任何能力。

## 结论

| 原则 | 具体动作 |
| --- | --- |
| 先分类再读 | 30 秒判断 A 类还是 B 类；B 类只需 L1/L2 |
| 深度按相关度分配 | 和方向无关的，再重要也只配 L1 |
| 读不懂就降级 | 不要硬扛，降一级（原文 → 解读 → 视频） |
| 数学按需补 | 判断装饰还是核心；只查这一个概念 |
| 全局视角靠画图 | 每学期画一张领域演变图，进 Excalidraw |
| L2 必须输出 | 200 字用自己的话，否则等于没读 |
| 工具要当过滤器 | 日报的价值是砍掉 95%，不是让你看完 100% |

**最低可执行版本**：每天 15 分钟扫日报 → 每周选 1 篇写 200 字 → 每学期复现 1 个 + 画 1 张演变图。
