# 摊还分析（Amortized Analysis）

## 一句话

**单次操作可能很贵，但一长串操作的总代价摊到每次是便宜的。**

## 为什么需要它

动态数组的 `append`：

- 绝大多数时候是 O(1)（`data[size++] = e`）。
- 偶尔触发扩容，要复制全部 n 个元素，单次 **O(n)**。

那么 `append` 的复杂度到底是多少？

- 说 O(1) 是**错的**——最坏情况确实是 O(n)。
- 说 O(n) 是**过度悲观**——连续追加 n 次的总代价明明是 O(n)，不是 O(n²)。

摊还分析就是回答这个问题的工具：它给出的是**一整个操作序列的平均代价上界**，而且是**最坏情况下的**序列上界（不是概率意义上的期望）。这是它和「平均复杂度」最本质的区别——平均复杂度依赖输入的分布假设，摊还分析不需要任何概率假设。

## 三种分析视角

**1. 聚合法（Aggregate）**——算总账再除。

设容量从 1 开始，每次满了翻倍，连续追加 n 次：

```
容量序列：1 → 2 → 4 → 8 → 16 → ... → ≥ n
搬运总量：1 + 2 + 4 + ... + n/2 < n
```

（等比数列求和：1 + 2 + 4 + … + 2^k = 2^(k+1) − 1 < 2n）

总代价 = n 次写入 + < n 次搬运 = O(n)，除以 n 次操作 ⇒ **每次摊还 O(1)**。

**2. 记账法（Accounting）**——每次便宜操作多收一点「费」，存起来付未来的贵操作。

每次 `append` 收 3 个代币：1 个付自己的写入，2 个存着（分别「抵押」给新元素自己和被复制的那个旧元素）。可以证明任何时刻账户余额非负 ⇒ 摊还代价 O(1)。

**3. 势能法（Potential）**——定义势函数 Φ 度量「预存的代价」。

取 Φ = 2·size − capacity（翻倍扩容策略下），可证每次 `append` 的摊还代价 = 实际代价 + ΔΦ = O(1)。

> 三种方法结论一致；聚合法最好懂，势能法最通用（哈希表、并查集、splay 树都用它）。

## 反例：因子必须 > 1

**如果每次满了只把容量 +1 会怎样？**

容量序列：1 → 2 → 3 → 4 → … → n。第 i 次追加要搬 i−1 个元素。

```
总搬运 = 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```

摊还到每次是 **O(n)**，不是 O(1)。**摊还 O(1) 不是「动态数组的天然属性」，而是「成倍扩容策略」换来的。** 把因子改成 10 倍，总搬运仍是 O(n)（约 1.11n），代价变成空间浪费——这就是权衡。

## 摊还 ≠ 平均

| | 摊还分析 | 平均复杂度 |
| --- | --- | --- |
| 输入假设 | **不需要**任何概率假设 | 依赖输入分布 |
| 结论性质 | 最坏情况下的序列上界 | 期望值 |
| 保证 | 「n 次操作总代价 ≤ f(n)」一定成立 | 「大概率是这样」 |

所以对实时系统，摊还 O(1) 仍可能不够——某一次操作真的会卡 O(n)。**摊还结论必须连同「最坏单次」一起说。**

## 其他靠摊还才成立的结构

- **哈希表扩容**——装载因子超阈值时整体 rehash，摊还 O(1)。
- **并查集路径压缩 + 按秩合并**——单次 O(α(n))，α 是反阿克曼函数（实际 < 5）。
- **栈的 `multipop`**——连续弹出 k 个的总代价摊还 O(1)（教材经典例题）。
- **splay 树**——单次可能 O(n)，摊还 O(log n)。
