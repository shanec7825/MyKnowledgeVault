# 数据结构分析框架

> 一句话主线：**数据结构 = 数据的逻辑关系 + 物理存储 + 操作集合 + 效率权衡。**
> 这不是定义，是**分析流程**。整门课的所有结构都能被这四个格子拆开。

## 一、四问：看任何一个结构都问这四个

| 问题 | 在问什么 | 例子（哈希表） |
| --- | --- | --- |
| 1. 表示什么关系？ | 逻辑结构 | 集合（键→值映射，无序） |
| 2. 支持哪些操作？ | ADT 契约 | `insert(k,v)` / `delete(k)` / `search(k)` |
| 3. 怎么存？ | 物理实现 | 数组 + 链地址法，或开放寻址 |
| 4. 代价是什么？ | 效率权衡 | 平均 O(1)，最坏 O(n)；空间换时间 |

**关键**：第 1 和第 3 是**两层不同的东西**。逻辑结构只有四种（线性、层次、网络、集合），物理实现只有五种（顺序、链式、索引、散列、混合），它们的笛卡尔积就是全部数据结构。这就是为什么「栈」既可以是数组也可以是链表——逻辑结构决定它能做什么，物理实现决定它做得多快。

## 二、六问法：面对真实问题的需求拆解

选型错，通常不是不懂结构，而是**没问清楚约束**。拿到问题先填这六格：

1. **数据规模多大？** 100 / 10 万 / 10 亿——规模跨越一个数量级，答案就换人（内存 → 磁盘 → 分布式）。
2. **主要操作是什么？** 查找 / 插入 / 删除 / 遍历 / 范围查询 / 最值——「主要」指占比最高的那个，不是全部。
3. **读写比例如何？** 读多写少 → 可以索引化、可以预计算；写多读少 → 优先 O(1) 写入（追加、LSM）。
4. **是否需要有序、范围、最值？** 需要有序就不能只上哈希；需要最值就考虑堆；需要范围就考虑树或跳表。
5. **约束是什么？** 内存上限、磁盘、网络、并发、缓存局部性——同一结构换到磁盘上会完全变形。
6. **能接受最坏情况吗？** 平均好 ≠ 最坏可接受。实时系统、关键路径看最坏；离线批处理看平均。

> 六问法的产出不是答案，是**把「哪个结构好」这个不可判定的问题，变成一个可判定的约束集合**。

## 三、四步：从问题到实现的学习动作

1. **画图**——先画逻辑关系（谁连着谁），不急着写代码。图画不对，代码一定错。
2. **定 ADT**——列出操作清单和契约（越界怎么办？允许重复吗？位置从 0 还是 1 开始？）。契约不明确，实现和测试都无法判定对错。
3. **选物理结构**——顺序 / 链式 / 索引 / 散列，用四问里的第 3、4 问做依据。
4. **分析复杂度**——时间、空间、最坏、平均、摊还。**摊还**常被漏掉，但动态数组、哈希表扩容、并查集路径压缩全靠它。

## 四、五种边：让知识成为网而不是点

每学一个新结构，至少连这五类边，否则三个月后必然遗忘：

| 边类型 | 问法 | 例子 |
| --- | --- | --- |
| **前置** | 它建立在什么之上？ | 哈希表 ← 数组 + 链表 + 哈希函数 |
| **对比** | 它替代谁？谁替代它？ | 哈希表 ↔ 二叉搜索树、跳表 |
| **组合** | 它能拼出什么？ | 哈希表 + 双向链表 = LRU 缓存 |
| **应用** | 它出现在哪？ | 字典、缓存、数据库索引、路由表、去重 |
| **关联课程** | 谁在用同一个结构？ | 数据库、操作系统、网络、分布式系统 |

## 五、避坑清单

- 不要只背代码，要会比较和选择——面试和工程里问的都是「为什么选它」。
- 不要忽略边界：空结构、重复元素、极端规模、越界。
- 不要只看平均，关键系统要看最坏。
- 不要只学单机——很多结构在磁盘、并发、分布式下会变形（B+树、一致性哈希、LSM）。
- 不要孤立学习——每学一个结构，问它替代谁、被谁组合、用在哪里。
