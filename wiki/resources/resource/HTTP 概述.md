# HTTP 概述

- **来源**：[MDN Web Docs — HTTP 概述](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/Overview)（最后修订 2025-07-04）
- **权威性**：official（MDN 是 Web 平台标准的官方文档站，HTTP 语义的权威一手表述）
- **摄入文件**：`inbox/HTTP 概述.md`
- **摄入日期**：2026-08-29

MDN《HTTP 概述》是 HTTP 的官方入门总纲：协议定位与在协议栈中的位置，客户端—服务器—代理三方构成，四项基本性质（简约 / 可扩展 / 无状态但有会话 / 依赖可靠连接），HTTP 能控制的五类特性，一次完整 HTTP 流的四步，以及请求与响应报文的字段构成。相比 Cloudflare 的《[[What is HTTP]]》（词汇表层级的速览），本篇给出了协议骨架的完整轮廓，是 [[wiki/projects/HTTP|HTTP]] 项目的第一份摄入来源。

## 关键论断

### 协议定位

- HTTP 是**应用层协议**，用于获取 HTML 文档等资源，是 Web 上一切数据交换的基础。
- 位于 TCP（传输层）与 IP（网络层）之上；理论上是"任何可靠传输协议"而不仅限于 TCP。
- 客户端与服务端交换的是**一个个独立的消息**，而非数据流。

### 系统组成

- **用户代理**：代表用户行为的工具（以浏览器为主），**总是**由它首先发起请求。
- **Web 服务器**：提供文档，可以是一台机器、一组负载均衡集群，或按需生成文档的软件；借助 HTTP/1.1 的 `Host` 标头，多个服务实例可共用同一 IP。
- **代理**：在应用层参与消息传递的实体，可以透明转发也可以改写请求，用途包括缓存、过滤、负载均衡、认证、日志。

### 基本性质

- **简约**：报文人类可读，便于测试与上手（HTTP/2 引入帧后这一性质被削弱）。
- **可扩展**：标头机制让新功能只需双方协商语义即可加入。
- **无状态但有会话**：同一连接中两个成功请求之间没有关系；Cookie 借标头扩展机制补上了有状态会话。
- **与连接的关系**：连接由传输层控制，不属于 HTTP 范畴；HTTP 只要求传输可靠，故依赖 TCP 而非 UDP。

### 连接与版本

- HTTP/1.0：每对请求 / 响应开一条独立 TCP 连接，连续请求时效率低。
- HTTP/1.1：引入**流水线**（已被证明难以实现）与**持久化连接**，可通过 `Connection` 标头部分控制底层 TCP。
- HTTP/2：在一条连接上复合多条消息，保持连接活跃。
- 更远的实验：Google 的 QUIC，基于 UDP 构建更可靠的传输。

### HTTP 能控制什么

- **缓存** — 服务端指示代理与客户端缓存什么、缓存多久；客户端可要求中间缓存忽略已存储文档。
- **开放同源限制** — 浏览器默认只允许同源页面互取信息，服务端可用标头放松这一限制（有安全代价）。
- **认证** — 通过 `WWW-Authenticate` 等标头或 Cookie 会话实现访问控制。
- **代理与隧道** — 内网机器经由代理越过网络屏障；并非所有代理都是 HTTP 代理（SOCKS 在更底层）。
- **会话** — 用 Cookie 把不同请求联系成会话，尽管协议本身无状态。

### HTTP 流

1. 打开 TCP 连接（新建、重用，或开多条）。
2. 发送 HTTP 报文（HTTP/2 之前人类可读；HTTP/2 中封装进帧）。
3. 读取服务端返回的报文。
4. 关闭连接，或为后续请求重用。

### 报文

- **请求** = 方法（`GET` / `POST` / `OPTIONS` / `HEAD` …）+ 资源路径（去掉协议、域名、端口后的 URL 部分）+ 协议版本 + 可选标头 + 可选请求体。
- **响应** = 协议版本 + 状态码 + 状态信息（不权威的简短描述）+ 标头 + 可选主体。
- HTTP/2 把上述报文嵌入**帧**这一二进制结构，以支持标头压缩与多路复用；**语义不变**，客户端会重组出原始的 HTTP/1.1 请求。

### 基于 HTTP 的 API

- **Fetch API** — 在 JavaScript 中发起 HTTP 请求的最常用 API，取代了 `XMLHttpRequest`。
- **Server-sent 事件** — 借助 HTTP 作为传输机制的单向服务，客户端用 `EventSource` 接收服务端事件。
