# 计算机本科学习手册：从课程到前沿，用知识库复利成长

> 适用对象：计算机专业本科生（大一到大四均可）。
> 使用前提：你的电脑上已经配好 claude-obsidian 知识库（Obsidian + Codex + Claude Code）。
> 这本书不是课程笔记，而是一套“怎么学”的操作系统：宏观选模式，微观跑动作，一切沉淀进你的知识库。

---

## 第 0 部分：先把循环跑起来（15 分钟上手）

这本书的所有方法都围绕同一个循环，先把它跑一遍，后面所有章节只是把每一环做深：

```text
收集(Capture) → 入库(Ingest) → 连接(Connect) → 使用(Use) → 复盘(Review)
```

对应到你的知识库：

| 环节 | 动作 | 工具/技能 |
|---|---|---|
| 收集 | 把看到的资料丢进 `inbox/` | 手动复制、`defuddle` 抓网页 |
| 入库 | 把素材变成带引用的笔记 | `/claude-obsidian:wiki-ingest` |
| 连接 | 建索引、知识地图、画布 | `wiki-index`、`canvas` |
| 使用 | 基于库回答问题、检索、检查 | `wiki-query`、`wiki-retrieve`、`wiki-lint` |
| 复盘 | 定期整理、归档日志 | `wiki-fold`、`think`、`wiki-mode` |

现在做一遍（在 WSL 终端）：

```bash
# 1. 打开知识库并启动 Claude Code
cd /mnt/c/Users/Lenovo/Documents/MyKnowledgeVault && claude

# 2. 在 Claude Code 里依次执行
/claude-obsidian:wiki            # 检查知识库状态
/claude-obsidian:save            # 把这条命令笔记存进库
/claude-obsidian:wiki-query "知识库有哪些主题"
/claude-obsidian:wiki-lint       # 看有没有死链
```

跑完这一遍，你已经理解这本书 80% 的操作内核。剩下的是：什么时候收集什么、怎么把每一步做深、以及如何让库里的知识真的复利。

## 第一部分 宏观：先选对模式

### 1.1 三条路线：工程、研究、产品

本科阶段最贵的资源是时间。先定路线，再分配时间，不要“什么都学一点”。

| 路线 | 目标 | 关键证据 | 时间分配建议 |
|---|---|---|---|
| 工程（就业） | 毕业能上手工业级开发 | 项目作品集、实习、开源贡献 | 60% 项目，25% 课程，15% 刷题 |
| 研究（深造） | 发表论文、读研/读博 | 论文、复现实验、导师推荐 | 50% 课程打底，35% 科研，15% 数学 |
| 产品（创业/全栈） | 做出被使用的作品 | 独立产品、用户、商业闭环 | 50% 产品，30% 工程，20% 通识 |

怎么选：

1. 大一到大二上，三条线都试：做一个完整小项目（工程）、跟一次组会或读 10 篇论文（研究）、发布一个小产品给真人用（产品）。
2. 大二下之前定主路线，另一条降为副线。
3. 路线可以换，但换的时候要留证据：作品集、论文笔记、产品复盘，全在知识库里，随时可回溯。

### 1.2 知识库方法论模式：PARA / LYT / Zettelkasten

你的知识库支持四种“归档模式”，用 `/claude-obsidian:wiki-mode` 切换。关键不是选哪个高级，而是匹配当前阶段：

| 模式 | 核心思想 | 适合阶段 | 使用场景 |
|---|---|---|---|
| Generic | 来源/概念/实体分桶 | 刚上手 | 默认兜底 |
| PARA | 按项目(Projects)组织一切 | 课程学习、工程路线 | 每门课=一个项目，作业=任务 |
| LYT | 用 MOC（内容地图）链接原子笔记 | 知识开始变多 | 建立“知识地图”导航 |
| Zettelkasten | 永久笔记+密集链接 | 科研、写作 | 论文卡片、思想复利 |

给你的默认建议：

- 大一～大二（打基础）：**PARA**。每门课一个 Project，材料进 Resources，学完归档进 Archive。
- 大二下～大四（分化期）：工程路线维持 PARA；研究路线切 **Zettelkasten**；知识量大之后切 **LYT** 建地图。
- 切换只影响新笔记的去向，不会打乱旧笔记，放心切。

### 1.3 使用模式：记录型 vs 建构型

这是大多数人的分水岭。

- **记录型**：上课抄笔记 → 存进库 → 再也不看。知识库变成垃圾桶，只增加存储，不增加能力。
- **建构型**：每条入库的资料必须回答“这条帮我解决了什么问题/改写了我的哪个理解”。库里的条目之间互相链接，查询时能拼出新的答案。

建构型的三条硬规则：

1. **入库即提炼**：`wiki-ingest` 之后，手动补一句“这条和已有的哪条冲突/互补”。
2. **每周至少一次 `wiki-query`**：用旧知识回答新问题，才叫复利。
3. **删除是合法的**：三个月没被任何链接引用的笔记，要么归档要么合并。

### 1.4 学期级规划模板

每学期开学第一周，做一次 20 分钟的规划，写进 `wiki/hot.md`：

```text
## 本学期目标（最多 3 个）
1. 主线目标（例：数据结构与算法达到能独立做出 80 道题）
2. 副线目标（例：完成一个开源贡献 / 读完 10 篇论文）
3. 生存目标（例：GPA ≥ 3.5，每周运动 3 次）

## 课程 → 项目映射
课程A → 期末项目 + 2 个课程笔记
课程B → 实验报告全部入库

## 里程碑
第 4 周：xxx   第 8 周：期中复盘   第 14 周：xxx
```

## 第二部分 中观：课程地图与技能树

### 2.1 计算机本科核心课程地图

下面的顺序是大方向，不是严格年级限制。每门课后面标注了“这门课的产出标准”——达到它，这门课才算真正学完。

#### 第 1 层：地基（大一～大二上）

| 课程 | 这门课真正教的东西 | 产出标准 |
|---|---|---|
| 高等数学/线性代数 | 抽象与推导的耐心 | 能不看答案推导核心定理 |
| 离散数学 | 计算机的“语法” | 能自己建模简单问题 |
| 概率论与数理统计 | 不确定世界的语言 | 能读懂算法的期望分析 |
| 程序设计（C/Python） | 把想法变成可运行程序 | 独立完成 2000 行以上项目 |

#### 第 2 层：核心（大二～大三）

| 课程 | 真正教的东西 | 产出标准 |
|---|---|---|
| 数据结构与算法 | 数据组织与问题求解 | LeetCode 中等题独立 AC 150+ |
| 计算机组成/体系结构 | 程序怎么在机器上跑 | 能做简易 CPU/汇编实验 |
| 操作系统 | 资源管理的艺术 | 能讲清进程/内存/文件系统并做小实验 |
| 计算机网络 | 端到端的系统思维 | 能抓包讲清一次请求的完整旅程 |
| 数据库系统 | 数据持久化与查询 | 能设计并解释一个三范式 schema |
| 编译原理 | 程序语言的形式化 | 能写一个 mini 编译器 |
| 软件工程 | 协作与质量 | 完成一个 2 人以上的真实协作项目 |

#### 第 3 层：方向（大三～大四）

| 方向 | 代表课程 | 判断标准：你是否真的喜欢 |
|---|---|---|
| 人工智能/机器学习 | 机器学习、深度学习、NLP/CV | 愿意为跑通一个模型熬夜 |
| 系统 | 分布式系统、高性能计算、存储 | 对“并发/一致性/性能”着迷 |
| 安全 | 网络攻防、密码学 | 喜欢找漏洞和攻防对抗 |
| 图形/游戏 | 计算机图形学、游戏引擎 | 享受可视化的即时反馈 |
| 数据库/数据工程 | 大数据、数据挖掘 | 喜欢处理真实脏数据 |

### 2.2 每门课的最小闭环

一门课的学习闭环，和知识库的循环一一对应：

```text
课前预习(收集) → 课堂笔记(入库) → 作业/实验(连接) → 考前复习(使用) → 期末复盘(归档)
```

每门课结束时，知识库里必须有：

1. 一个课程主页（`wiki/` 下，链接到所有相关笔记）
2. 10 条以上“结论型”笔记（每条 = 一个概念 + 一句话解释 + 一个例子 + 一个链接）
3. 至少 2 个课程项目复盘（见附录 B 模板）

### 2.3 技能树与并行安排

课程之外，三条技能线并行推进，每条每天 30 分钟即可：

- **工具线**：Git/GitHub、Linux 命令行、VSCode、Docker、调试器（GDB/浏览器 DevTools）
- **语言线**：主语言（C++/Java/Python 任选一门钻深）+ 一门脚本语言
- **英语线**：文档阅读 → 论文阅读 → 英文写作（技术博客/邮件）

## 第三部分 微观：每天、每周、每学期的具体操作

### 3.1 每日学习循环

给一个可执行的时间块示例（周末版本，工作日按课表调整）：

```text
上午 09:00-10:30  深度模块 1（课程最难的部分，无手机）
上午 10:45-12:00  深度模块 2（刷题 / 写代码）
下午 14:00-15:30  深度模块 3（项目 / 论文）
下午 15:45-16:30  收尾仪式（见下）
晚上 20:00-21:00  英语 / 工具线
```

**收尾仪式（每天 10 分钟）**，这是知识库复利的关键：

```bash
cd /mnt/c/Users/Lenovo/Documents/MyKnowledgeVault && claude
```

1. 把今天产生的零散材料丢进 `inbox/`
2. `/claude-obsidian:wiki-ingest` 入库
3. `/claude-obsidian:save` 保存今天最重要的一个结论
4. 更新 `wiki/hot.md` 的“最近变化”

### 3.2 课堂笔记与教材阅读

**课堂笔记三段法：**

- 课前（10 分钟）：把教材目录抄成大纲，上课往里面填。
- 课中：只记“老师额外说的”和“没听懂的点”，PPT 内容课后补。
- 课后（20 分钟）：用费曼法重写——假装讲给大一新生听，卡住的地方就是漏洞。

**教材阅读（SQ3R 变体）：**

1. 浏览：看目录、图表、小节标题（5 分钟）
2. 提问：把每节标题改成问题（例：“进程和线程到底差在哪”）
3. 精读：带着问题读，找到答案就停
4. 复述：合上书，把答案写进笔记
5. 回顾：第二天、一周后各看一次

### 3.3 刷题方法论（OJ / LeetCode）

刷题不是为了数量，是为了形成“识别模式 → 套用范式”的直觉。

```text
分类练习（按数据结构/算法）→ 限时思考（20 分钟）→ 看题解 → 复盘入库
```

具体规则：

- 一道题最多独立想 20 分钟，没思路就看题解，不丢人。
- 题解必须写进知识库：这题属于哪类模式、关键观察是什么、和哪道旧题同构。
- 每周固定复习错题（用 `wiki-query "刷题复盘"` 拉出来重做）。
- 目标节奏：大一 100 题（简单为主），大二 200 题（中等为主），大三面试前按公司题库冲刺。

### 3.4 项目实践

项目是工程路线的唯一硬通货。项目阶梯：

1. **课程作业** → 不满足于“能跑”，加注释、加测试、写 README。
2. **个人小项目**（1-2 周）：解决自己真实的问题（自动整理下载文件夹、课程表提醒）。
3. **开源贡献**（1-3 个月）：从 docs/issue 入手，再修 bug，再提 feature。
4. **作品集项目**（一学期）：有真实用户、有架构设计、有部署上线。

每个项目结束时写一份复盘入库存档（模板见附录 B），这是面试时你讲故事的素材库。

### 3.5 复习与考试

- 平时：每次入库的笔记自带“下次复习日期”（间隔重复：1 天 / 3 天 / 7 天 / 30 天）。
- 考前两周：把课程所有笔记用 `wiki-fold` 压成一份提取式提纲，再做近三年真题。
- 考试本身不重要，重要的是你能用知识库 30 分钟内重建整门课的知识骨架。

### 3.6 周 / 月 / 季检查清单

**每周日（30 分钟）：**

- [ ] `wiki-lint` 跑一遍，修死链
- [ ] 清空 inbox（超过一周没处理的，要么入库要么删）
- [ ] 回顾本周 3 个最重要的结论，写进 `wiki/hot.md`
- [ ] 刷题错题重做 3 道

**每月（1 小时）：**

- [ ] `wiki-fold` 把本月操作日志压成月度摘要
- [ ] 检查目标进度，偏差超过 20% 就调整计划
- [ ] 删/合并 3 个月没被引用的笔记

**每学期（半天）：**

- [ ] 学期复盘：完成了什么、没完成什么、为什么
- [ ] 课程笔记归档到 Archive
- [ ] 更新下学期的规划模板

## 第四部分 前沿：跟上、读懂、参与

### 4.1 读论文三遍法（并入库）

论文阅读不是从头读到尾，而是三遍：

1. **第一遍（5 分钟）**：读标题、摘要、结论。回答三个问题：这篇解决什么问题？方法一句话是什么？结果有多好？不够感兴趣就停。
2. **第二遍（30 分钟）**：读图表、方法、实验。在论文卡片里记录：问题、方法、结果、局限、和自己的知识库哪条笔记相关。
3. **第三遍（可选）**：对着公式/代码逐行复现。只有你准备以这篇为起点做研究时才需要。

论文卡片模板见附录 B。卡片入库后，`wiki-query "论文"` 就能检索你的全部阅读史。

### 4.2 信息源配置

每天固定 20 分钟，来源宁缺毋滥：

- **论文**：arXiv（cs.AI / cs.LG 等分类）、会议（NeurIPS / ICML / ICLR / CVPR / ACL / OSDI / SIGCOMM）
- **博客**：跟随你方向里 5-10 个大牛的个人博客，比刷新闻有效
- **社区**：GitHub Trending（看项目）、Hacker News（看讨论）、对应方向的中文社区（看入门）
- **代码**：把 star 的仓库克隆下来，跑通 demo 再谈看懂

### 4.3 本科生科研入门

研究路线的最小路径：

1. **复现**：选一篇你方向里引用量高、代码开源的论文，完整复现（1-2 个月）。
2. **改进**：在复现基础上改一个变量，记录结果差异，写成实验报告入库。
3. **综述**：用你的论文卡片库写一个小综述（10-20 篇），这是和导师沟通的敲门砖。
4. **找导师**：带着你的复现报告和综述去谈，比空手说“我想进组”强十倍。

### 4.4 AI 时代的学法：Codex / Claude 的正确用法

你有别人没有的工具，但要设边界，否则工具会替你学习：

**可以问 AI 的：**

- 概念的第一遍解释（然后自己复述入库）
- 调试报错、查 API 用法
- 代码 review、重构建议
- “我的理解对不对”的验证

**必须自己做的：**

- 作业、考试、实验的最终产出
- 从零设计一个方案（AI 只当顾问）
- 面试算法题的手写
- 任何需要“肌肉记忆”的技能（语法、快捷键、调试）

一句话原则：**AI 是用来压缩查找时间的，不是用来压缩思考时间的。** 每次让 AI 帮忙后，用 `/claude-obsidian:save` 把“这次学到的模式”存进知识库——这才是把 AI 变成你的复利。

### 4.5 前沿地图：AI 时代的主线

如果你是 2020 年代入学的 CS 本科生，AI/ML 是你绕不开的主线，但不必人人做算法：

- 做应用：LLM 应用开发、RAG、Agent 系统、提示工程 → 工程路线
- 做系统：大模型训练/推理优化、分布式、异构计算 → 系统路线
- 做算法：模型结构、训练方法、对齐、可解释性 → 研究路线
- 做交叉：AI + 你的兴趣（医疗/金融/教育/游戏）→ 差异化优势

## 第五部分 更多：路线之外的事

### 5.1 实习与求职时间线

```text
大二暑假：小公司/远程实习，先有第一段经历
大三上：准备简历 + 刷题 + 项目复盘
大三下：暑期实习投递（提前批在前一年秋冬开始）
大四秋招：金九银十主力批次
```

简历上每一条经历都要能在知识库里找到对应复盘，面试时才能讲出细节。

### 5.2 开源参与

选一个你每天都用的开源项目，从“读代码 → 报 issue → 修文档 → 修 bug”逐步升级。参与开源是简历上最硬的“分布式协作”证明。

### 5.3 英语

- 工具：文档和论文用英文原版，中文只做辅助。
- 输出：技术博客用英文写，或中英双语。
- 目标：大四前能 30 分钟读完一篇论文、10 分钟写一封技术邮件。

### 5.4 精力与时间管理

学习是马拉松：

- 睡眠固定 7-8 小时，比多学 1 小时更划算
- 每周 3 次运动，每次 30 分钟以上
- 每天 1 个“深度模块”优先于 3 个“浅度模块”
- 手机放另一个房间，专注时不看消息

### 5.5 原则清单（贴在知识库首页）

1. 先跑通，再优化；先完成，再完美。
2. 输入必须变成输出（笔记/代码/复述），否则等于没学。
3. 不懂就问 AI，但复述和产出必须自己来。
4. 每周复盘一次，比每天自责有效。
5. 路线可以换，证据不能丢——一切存进知识库。

### B1 课程笔记模板

```markdown
---
type: course
title: 课程名 - 章节名
course: 课程名
created: {{date}}
tags: [course, {{课程名}}]
---

# 章节标题

## 核心问题（课前预习时写下）

## 概念卡片（每个概念一条，课后费曼重写）
### 概念名

- 例子：
- 易错点：
- 链接：[相关笔记]({{相关笔记}})

## 本节课我没听懂的点
- [ ] 点 1（计划何时解决）
- [ ] 点 2

## 作业/实验心得
```

## 附录 C：30 天启动计划

第 1-3 天：跑通第 0 部分的循环，把知识库用顺手。
第 4-7 天：选路线（先按默认 PARA），写学期规划。
第 8-14 天：给本学期最难的一门课建课程主页，每天课后 20 分钟入库。
第 15-21 天：启动刷题节奏（每天 1 道 + 复盘），同时跑第一个 1 周小项目。
第 22-28 天：读 3 篇论文（第一遍即可），建论文卡片；写第一篇英文技术笔记。
第 29-30 天：周/月检查清单跑一遍，`wiki-fold` 压月报，调整下月计划。
