# 2026-08-29

## Dataview 持续失效：磁盘侧彻底排查 + 改用 DataviewJS

用户连续三轮报告 area 页的 dataview 检索不出项目（先「全是认知科学的」，后「为空」，再「失败」）。**磁盘侧全部查清，无问题**：

1. PyYAML 严格校验 14 个 project 的 frontmatter —— 全部合法，`area` 值全部正确（`'后端'`×7、`'人工智能'`×2、`'神经与认知科学'`×5）。
2. frontmatter 字符检查 —— 无 tab、无 NBSP/全角空格/中文引号/BOM/零宽字符，缩进与列表格式规范（js-yaml 比 PyYAML 严格，这些会让 Obsidian 丢弃整个 frontmatter）。
3. `.obsidian/app.json` 的 `userIgnoreFilters = ['.raw/', '.vault-meta/']` —— 不含 `wiki/projects`，无排除问题。
4. Dataview 0.5.68 已启用，`refreshEnabled`、`enableDataviewJs` 均为 true。

尝试过的三版查询与结果：
- v1 `WHERE area = this.file.name ...` → 串领域（this 在悬浮预览/嵌入时指向别的文件）
- v2 `WHERE (area = "后端" OR area = this.file.name) ...` → 未验证即弃用（OR 兜底反而是污染源）
- v3 `WHERE area = "后端" ...` → 空
- v4 `FROM "wiki/projects" AND #area/后端` → 失败（怀疑 DQL 解析器对中文 tag 处理有问题）

**最终方案：改用 DataviewJS**（三个 area 页 + 模板已改）：
```dataviewjs
const AREA = "后端";
dv.pages('"wiki/projects"')
  .where(p => p.area === AREA && p.status !== "completed")
```
理由：JS 的中文字符串比较是原生的，绕过 DQL 解析器；领域名硬编码，避开 `dv.current()` / `this` 的指向问题。CLAUDE.md 第 4 节已写入该纪律 + 一份「Dataview 不工作排查清单」（先跑无 WHERE 的 LIST 验证索引 → 查 userIgnoreFilters → 查 frontmatter 隐蔽字符 → 重载 → 查版本）。

**教训**：中文 vault 里，Dataview 的 DQL 字符串字面量与中文 tag 都不可靠，涉及中文值比较一律走 DataviewJS。

## 工具坑（重要）

- **Bash heredoc 会破坏反斜杠转义**：`\s` 被转成 `/s`，导致 Python 内联正则静默失效（曾误报「area=None」）。多行 Python 脚本必须 Write 成文件再执行。
- **Write 到 `drafts/` 偶发不落盘**：同一 turn 内 Bash 看不到该文件（沙箱视图不一致），但改动可能在下个 turn 生效。关键改动优先用 Edit 工具直接改目标文件，不要绕道临时脚本。
- Python 写文件必须 `newline="\n"`，否则 Windows 下 LF 变 CRLF。
