## 方法论沉淀

- 「完整可运行」类交付的验收方式 = **测试断言 + 基准实测数字**，不要只交源码。
- 本轮先写 Python 复算期望值（growCount=14、moveCount=131064、头插 49995000、缩容 1024→512），
  **再**编译 C++。好处是避免「编译通过但断言值写错」这种最难查的失败。
- MSYS2 免安装部署路径：`mirrors.tuna.tsinghua.edu.cn/msys2/distrib/msys2-x86_64-latest.tar.xz`
  → Python `tarfile.open(...,'r:xz')` 解压 → 改 mirrorlist → `pacman-key --init && pacman-key --populate msys2`
  → `pacman -Sy --noconfirm --needed mingw-w64-x86_64-gcc`。全程不需要 GUI 安装器。

## 踩坑记录（下次直接用）

1. **`pacman-key --init/--populate` 在 Windows 上会卡进 gpg 锁文件死循环**（刷出 4.7 MB 的
   `gpg: removing stale lockfile`）。绕过：`/etc/pacman.conf` 把 `SigLevel = Required` 改成 `Never`，
   然后 `pacman -Sy && pacman -S --noconfirm --needed mingw-w64-x86_64-gcc`，**完全跳过密钥环**。
2. **MinGW 的 `cc1plus` 读不了含非 ASCII 字符的绝对路径**。`g++ -o /d/Projects/线性表/...` 报
   `cc1plus.exe: fatal error: ... No such file or directory`；但 `cd` 进目录后用**相对路径**完全正常。
   ⇒ 构建脚本必须先 `cd` 到项目根再传相对路径（`scripts/build.sh` 已这么写）。
3. **期望值先算再编译**：本轮先用 Python 复算期望值，结果发现「头插搬运」应是 50 011 376
   而不是 49 995 000 —— 差额正是扩容复制量。若照 `N(N−1)/2` 写死断言，就会误判成失败。
