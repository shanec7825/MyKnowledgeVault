## 第 1 章 命令行是什么

### 1.1 终端、Shell 与内核：三个角色

很多人把「黑窗口」叫命令行，其实里面藏着三个不同的角色。分清它们，后面很多现象就不奇怪了：

| **角色**         | **它是什么**                                                     | **类比**                             |
|------------------|------------------------------------------------------------------|--------------------------------------|
| 终端（Terminal） | 负责显示文字、接收你敲的键，只是一块「屏幕 + 键盘」              | 餐厅里的桌椅和菜单板                 |
| Shell（外壳）    | 读你的命令、解析语法、找到对应程序并启动它。bash、zsh 都是 Shell | 点菜的服务员：听懂你的话，传达给后厨 |
| 内核（Kernel）   | 真正干活的系统核心：创建进程、读写文件、分配内存都由它执行       | 后厨：所有实际工作在这里完成         |

**一句话记忆：**你对终端说话，Shell帮你翻译，内核替你干活。

### 1.2 一条命令的旅程

按下回车之后发生了什么？记住这条流水线，很多调试直觉就建立在它上面：

> \$ ls -l ~/project0
>
> │ │ └──④ 参数：命令处理的对象
>
> │ └─────③ 选项（开关）：改变命令的行为
>
> └────────② 命令名：要运行哪个程序
>
> ① Shell 按空格切分，识别出 命令 / 选项 / 参数
>
> ⑤ Shell 去 PATH 列出的目录里找同名程序
>
> ⑥ 找到后由内核创建新进程来运行它
>
> ⑦ 程序把结果打印到屏幕；结束后进程消失，Shell 显示新提示符

提示符（prompt）末尾的 \$ 表示普通用户；# 表示 root（管理员）。命令行大小写敏感：ls 和 LS 是两个东西。

> **【辅助记忆 · 拆解口诀】**「命令 选项 参数」——选项调口味，参数指对象。ls 是菜名，-l 是做法，~/project0 是给谁做。

### 1.3 三条救命键

| **按键**     | **作用**                                  | **记忆点**                     |
|--------------|-------------------------------------------|--------------------------------|
| Tab          | 自动补全命令名/路径（按两次列出所有候选） | 能少打一个字就少打一个字       |
| ↑ / ↓        | 翻出上一条/下一条历史命令                 | 重复命令不用重敲               |
| Ctrl + C     | 立刻终止当前正在运行的命令                | 「C = Cut/Cancel」，卡住就按它 |
| Ctrl + L     | 清屏（等价于 clear）                      | 屏幕太乱时的橡皮擦             |
| Ctrl + R     | 搜索历史命令（输入关键字反查）            | 记得大概、忘了全名时用         |
| Ctrl + A / E | 光标跳到行首 / 行尾                       | A = Ahead（开头），E = End     |

### 1.4 为什么学命令行（和项目 0 的关系）

项目 0 的观察工具全部是命令行工具：

- gcc —— 把 C 源文件变成可执行文件（编译、汇编、链接）

- gdb —— 让程序走一步看一步，观察寄存器和局部变量

- objdump —— 把可执行文件「拆开」，看里面的机器指令

- strace —— 记录程序运行时向内核提出的每个请求（系统调用）

- cat / ls / cd —— 查看构建产物：源文件、目标文件、可执行文件各是什么样

它们的共同点是：没有图形界面，全部靠「输入命令 → 读输出」完成观察。命令行不是落伍的工具，而是离系统最近的观察窗口——输出可以复制、存档、对比，这正是项目 0 要求你「保存关键输出作为证据」的原因。

## 第 2 章 文件系统与路径

### 2.1 目录树：一切皆文件

Linux 把所有东西都组织成一棵树：最顶端是根目录 /，所有文件、目录、甚至硬件设备都挂在这棵树上。目录（directory）就是文件夹，路径（path）就是「从树根或当前位置走到目标的路线」。

### 2.2 三种路径写法

| **写法** | **含义**                                | **例子**                        | **记忆点**                    |
|----------|-----------------------------------------|---------------------------------|-------------------------------|
| 绝对路径 | 从根 / 开始的完整路线，在任何位置都有效 | /home/xiaoming/project0/main.c  | 开头一定是 /，像完整邮寄地址  |
| 相对路径 | 从「当前位置」出发的路线，随位置变化    | project0/main.c                 | 不以 / 开头，像「往前走两步」 |
| ~        | 当前用户的家目录（home）                | ~/project0/main.c               | 「我的地盘」起点              |
| .        | 当前目录                                | ./a.out（运行当前目录的 a.out） | 「这里」                      |
| ..       | 上一级目录                              | cd ..（退回上一层）             | 「楼上」                      |
| \-       | 上一次所在的目录                        | cd -（在两个目录间来回跳）      | 「刚才那里」                  |

> / ← 根目录（树根）
>
> ├── home/
>
> │ └── xiaoming/ ← 家目录 ~
>
> │ └── project0/
>
> │ ├── main.c 源文件（你写的）
>
> │ ├── main.o 目标文件（gcc -c 的产物）
>
> │ └── a.out 可执行文件（链接后的产物）
>
> ├── usr/bin/ ← 常用命令（ls、gcc、gdb…）住在这里
>
> └── etc/ ← 系统配置

### 2.3 类比记忆

> **【路径类比】**绝对路径 = 完整邮寄地址「中国某省某市某路 1 号」，写全了谁都能找到；相对路径 = 「我家隔壁」，只有站在正确位置才成立。写脚本、写构建命令时优先用相对路径（项目可整体搬走），自己手动操作时用 ~ 少打字。

### 2.4 路径常见坑

- Linux 用 / 分隔路径，Windows 用 \\ ——WSL 里一律用 /。

- 路径或文件名带空格时必须加引号：cd "My Project"；项目 0 的目录名不要带空格。

- 大小写敏感：Main.c 和 main.c 是两个不同的文件。

- ./a.out 与 a.out 不同：默认情况下 Shell 不在「当前目录」找程序，必须写 ./ 前缀。（原因是安全：防止误运行当前目录里伪装成系统命令的文件。）

### 3.4 权限：rwx 到底是什么

Linux 用 9 个字母描述谁能对文件做什么。ls -l 显示的 -rw-r--r-- 就是它们：

> r w x r w x r w x
>
> ─┬── ─┬── ─┬──
>
> │ │ └── 其他人（other）
>
> │ └── 同组用户（group）
>
> └── 所有者（owner）
>
> r = read 读 w = write 写 x = execute 执行（对目录：能否进入）
>
> 对应数字：r=4 w=2 x=1，三者相加得每组的值
>
> 例：rwxr-xr-x → 7 5 5

chmod（CHange MODe）修改权限，两种写法都要会：

> \# 数字写法：每位 = r+w+x 之和
>
> chmod 755 run.sh \# 所有者 rwx，其他人 r-x
>
> chmod 644 notes.txt \# 所有者 rw-，其他人 r--
>
> \# 字母写法：u=所有者 g=组 o=其他人 +加 -减 =设定
>
> chmod +x run.sh \# 给所有人加执行权限（跑脚本最常用）
>
> chmod u+w main.c \# 给自己加写权限

项目 0 的典型场景：编译出的 a.out 想直接运行 ./a.out，没有 x 权限会报 Permission denied，用 chmod +x a.out 解决。

> **【辅助记忆 · 数字口诀】**「r 是 4，w 是 2，x 是 1，加一加就是七五五」。常见组合背三个就够：755（程序/脚本可执行）、644（普通文件）、700（私密目录）。

### 3.5 文本三剑客：grep、sed、awk

项目 0 的实验里你要在大量输出中找出关键证据，「三剑客」就是筛子和剪刀。这里只需掌握最常用的一层，够用即可：

#### grep —— 搜索（找哪一行）

> grep "printf" main.c \# 在文件里找含 printf 的行
>
> grep -n "add" main.c \# -n 顺便显示行号
>
> grep -r "TODO" project0/ \# -r 递归搜索整个目录
>
> objdump -d a.out \| grep "\<add\>:" \# 在反汇编输出里定位 add 函数

记忆点：grep = Global Regular Expression Print，把它理解成「按内容过滤行」。

#### sed —— 替换（改文本）

> sed 's/old/new/g' main.c \# 把 old 换成 new（s/原/新/g）
>
> sed -i 's/DEBUG/RELEASE/g' config.h \# -i 直接改文件（不加 -i 只打印不修改）

记忆点：s 是 substitute（替换），g 是 global（一行内全替换）。

#### awk —— 按列取值（拿第几列）

> ls -l \| awk '{print \$1, \$9}' \# 只打印第 1 列（权限）和第 9 列（文件名）
>
> ps -ef \| awk '{print \$2}' \# 只打印第 2 列（PID）

记忆点：\$1、\$2… 是第 1、2… 列（按空格切分）；把它理解成「表格取列器」。

## 第 4 章 命令的组合与自动化

### 4.1 重定向：让输出换个去处

默认情况下，命令的输出打到屏幕上（显示器）。重定向符号给输出「改道」：

| **写法**    | **作用**                 | **例子**                      | **记忆点**               |
|-------------|--------------------------|-------------------------------|--------------------------|
| \> file     | 把输出写入文件（覆盖）   | gcc main.c \> build.txt 2\>&1 | 箭头指向哪，输出就流向哪 |
| \>\> file   | 追加到文件末尾           | echo "ok" \>\> notes.txt      | 双箭头 = 追加            |
| \< file     | 把文件内容作为命令的输入 | sort \< names.txt             | 输入也走箭头             |
| 2\>&1       | 把错误输出并入正常输出   | make 2\>&1 \| less            | 2 = 错误流，1 = 正常流   |
| 2\> err.txt | 只把错误信息写进文件     | ./a.out 2\> err.txt           | 出错时才有内容           |

为什么要懂这个？项目 0 要求你「保存构建命令和关键输出作为证据」，用重定向直接把输出存档：

> gcc -g -Wall main.c -o a.out \> build_log.txt 2\>&1
>
> objdump -d a.out \> asm.txt \# 保存反汇编结果
>
> strace ./a.out \> trace.txt 2\>&1 \# 保存系统调用轨迹（strace 输出走 2）

### 4.2 管道：把命令串成流水线

竖线 \| 把左边命令的输出直接变成右边命令的输入，像流水线一样逐级加工：

> objdump -d a.out \| grep "\<add\>:" \# 反汇编 → 只挑出 add 函数
>
> ls -l \| wc -l \# 列目录 → 数有几行（几个文件）
>
> history \| grep gcc \# 历史记录 → 找出用过的 gcc 命令
>
> ps -ef \| grep a.out \| awk '{print \$2}' \# 找进程 → 只取 PID

读法：从左到右，「A 的结果喂给 B」。管道可以无限串联，每个 \| 都是一道工序。

> **【辅助记忆 · 水管比喻】**\> 是「改道的水管」（输出流进文件）；\| 是「接力棒」（上一个的输出交给下一个继续加工）。方向永远跟着箭头走。

### 4.3 通配符与引号

> \* 匹配任意长度的任意字符 ls \*.c 所有 .c 文件
>
> ? 匹配单个字符 ls main?.c main1.c、main2.c…
>
> \[abc\] 匹配括号内任一字符 ls \[ms\]\*.c m 或 s 开头的 .c

引号规则（很重要，脚本里常踩坑）：

- 双引号 " "：内部变量会展开。echo "\$HOME" 输出家目录路径。

- 单引号 ' '：内部一切原样输出。echo '\$HOME' 就输出 \$HOME 四个字符。

- 反引号 \` \` 或 \$( )：先执行里面的命令，用结果替换。echo "今天是 \$(date)"。

### 4.4 后台运行、历史与帮助

| **命令**    | **作用**                | **例子**              | **记忆点**         |
|-------------|-------------------------|-----------------------|--------------------|
| cmd &       | 命令放后台运行          | ./server &            | 结尾加 & 即可      |
| jobs / fg   | 查看后台任务 / 调回前台 | fg %1                 | Foreground         |

### 5.3 常用参数与选项记法

> gcc -g -Wall -O0 main.c -o a.out
>
> │ │ │ └── 输出文件名（默认 a.out）
>
> │ │ └── 优化级别 0（不优化，方便对照源码）
>
> │ └── 打开所有常见警告（强烈建议常开）
>
> └── 生成调试信息（gdb 要用，必加）
>
> \# -O 大写字母选项多为「模式」；-o 小写指定输出名；-g = debug info
>
> \# 选项可以合并：gcc -g -Wall 等价于写在一起（但 -o 后必须跟名字）

### 6.2 类比记忆库

- Shell = 服务员，内核 = 后厨，终端 = 餐厅。

- 绝对路径 = 完整邮寄地址，相对路径 = 「我家隔壁」。

- \> = 改道的水管，\| = 传送带接力。

- 文件权限 = 门禁卡：谁能进（r）、谁能改（w）、谁能用（x）。

- 目标文件（.o）= 半成品零件，可执行文件 = 装配好的机器，进程 = 机器发动起来。

- 断点（gdb break）= 在代码里设路障，程序跑到这里停下让你检查。

- strace = 给程序配的「通话记录」，记录它向内核提出的每次请求。

|-----------------------|--------------------------------|---------------------------------------------|
| ./a.out 写成 a.out    | bash: a.out: command not found | 运行当前目录程序必须加 ./                   |

| rm 删错文件           | 无法恢复                       | 先 ls 确认，再点名删除，少用通配符 \*       |

### 6.4 自测题（合上文档回答）

5.  ls -l 输出的第一列 -rwxr-xr-x 里，第一个 - 和后面的 rwx 各表示什么？数字记法是多少？

6.  如何在 objdump -d a.out 的输出中快速找到 add 函数？

7.  「保存 gdb 观察结果到文件」该用哪个符号？如果连错误信息一起保存呢？

8.  main.c、main.i、main.s、main.o、a.out 分别是哪个步骤的产物？

9.  gdb 的 next 和 step 有什么区别？

10. strace 和 objdump 的观察对象有什么本质区别？（提示：静态 vs 动态）

**参考答案：**

1\) 第一个 - 表示普通文件（d 是目录）；rwx 是所有者的读/写/执行；数字记法 755。2) objdump -d a.out \| grep "\<add\>:"。3) 用 \> 重定向；连错误一起保存用 2\>&1。4) main.c 源文件 → main.i 预处理 → main.s 编译（汇编文本）→ main.o 汇编（机器码）→ a.out 链接。5) next 执行下一行但不进入函数内部；step 会进入被调用的函数。6) objdump 看的是磁盘上文件里的静态机器指令；strace 看的是进程运行期间动态发生的系统调用。
