# 计算机系统基础课程大纲与前言

## 前言

计算机系统基础研究一个程序如何在真实机器上运行。我们从一段简单的 C 程序出发，观察它怎样经过编译和链接成为可执行文件，怎样被操作系统装入进程，怎样由 CPU 执行，以及怎样通过内存、文件和网络与外部世界交互。每个实验都回答这个过程中的一个具体问题。

高级语言把许多底层细节隐藏起来，使我们能够快速开发应用。但当程序出现错误、性能下降或并发问题时，仅理解源代码往往不够。我们需要知道变量可能存在哪里，函数调用怎样改变机器状态，内存访问为什么有成本，以及系统调用怎样影响程序的执行。

本课程采用几条并行主线逐渐汇合的组织方式。程序主线研究数据表示、机器指令、函数调用与链接；硬件与性能主线研究 CPU 状态、局部性和优化；操作系统主线研究进程、异常控制流、虚拟内存与 I/O；通信主线研究 socket、HTTP 和并发。这些主线在简化 Web Server 中建立联系。

学习从观察现象开始，但必须走到解释和验证。每次实验先写出预测，再运行程序，随后用汇编、调试记录、系统调用轨迹或测量数据检验预测。出现差异时，明确原先假设错在哪里，并设计下一次实验。系统思维就在这些具体的修正中形成。

课程适合已经接触 C 语言、希望把数字逻辑和软件开发连接起来的学习者。有后端框架使用经验，可以帮助理解综合项目的用途；底层概念仍需要通过小实验逐步建立。课程以用户态程序和软硬件接口为重点，并用简化 CPU 模型连接数字逻辑知识。

完成课程后，面对一个程序，你应能说明它的数据如何表示、关键代码怎样执行、资源由谁管理，并能够用工具寻找错误和性能瓶颈。进一步的目标是：换一段未见过的程序，仍能提出合理预测，并找到支持或否定预测的证据。

## 课程大纲

### 学习条件与课程边界

前置能力包括 C 的函数、数组、指针和结构体，以及基本的命令行操作。若指针或对象生命周期还不熟悉，可在项目 0 和项目 1 中补齐。建议使用 Linux 或 WSL，统一采用 C 与 x86-64 作为主要实验环境；简化 CPU 项目使用自行定义的教学指令集。

教材《深入理解计算机系统》用于查阅概念和补充练习，项目顺序不要求与章节顺序一致。完整操作系统内核、真实 CPU 设计和完整 TCP 实现属于后续课程范围。拓展任务可按兴趣选择，不作为进入下一项目的必备条件。

### 依赖关系与并行安排

建议先完成 0、1、2。项目 3 是连接数字逻辑的支线，可与项目 4 并行；项目 5 需要项目 1、2 的基础。随后完成 6、7、8，再进入 9、10。项目 7 与项目 8 可交替推进，性能测量方法则在后续项目中持续使用。

### 项目 0 系统观察与工具入门

一段 C 程序经过哪些步骤，才能成为正在运行的进程？

**前置知识：**基本 C 语法与命令行操作。

**核心内容：**编译、汇编、链接和执行；可执行文件与进程的区别；调试器、反汇编、系统调用轨迹与进程信息。

**实验任务：**编写带 add 函数和 printf 的程序；保存预处理、汇编和目标文件结果；在函数入口设置断点，观察寄存器和局部变量；运行时检查进程信息与系统调用。

**提交成果：**源程序、构建命令、关键截图或文本记录，以及一张标注各工具观察对象的流程图。

**验收标准：**能够解释源文件、目标文件、可执行文件与进程的区别；说明 gdb、objdump、strace 和 /proc 各自能提供什么证据。

**可选拓展：**比较带调试信息和不同优化级别的构建结果。

### 项目 1 数据表示与位运算

同一组位怎样被解释为不同的数据，表示范围又受什么限制？

**前置知识：**项目 0；整数、数组和指针基础。

**核心内容：**二进制与十六进制；无符号数、补码、类型转换、字节序；浮点编码与舍入；位运算及对象表示。

**实验任务：**实现按字节显示对象表示的工具；比较整数的不同解释；通过 memcpy 取得 float 的位模式；研究 0.1、0.2 的近似表示，以及加法后的舍入；实现掩码和字段提取。

**提交成果：**位模式查看工具、边界输入记录与浮点误差解释。

**验收标准：**给定固定位宽，能计算表示范围并解释转换；能区分无符号回绕和有符号溢出的语言规则；能说明有限精度为何影响加法。

**可选拓展：**设计一个小型浮点格式；比较浮点求和顺序的影响。

### 项目 2 机器级程序与函数栈

变量、分支、循环和函数调用怎样对应机器状态变化？

**前置知识：**项目 1；函数、指针和数组。

**核心内容：**寄存器、寻址方式、比较与跳转；调用约定、返回地址、栈帧和对齐；优化对源代码映射的影响。

**实验任务：**分析分支、循环、数组访问和递归的汇编；对照低优化与高优化版本；逐指令观察一次函数调用；用本地教学程序观察越界写导致的状态破坏，并修正边界检查。

**提交成果：**若干 C 与汇编对照案例，以及函数调用前后的栈和寄存器记录。

**验收标准：**能识别小段汇编中的循环、参数与返回值；能解释调用和返回；知道变量可能位于寄存器、内存或被优化掉，栈帧图必须注明实验条件。

**可选拓展：**在隔离的本地实验中比较栈保护等机制的效果。

### 项目 3 简化 CPU 模拟

CPU 怎样根据指令改变寄存器、内存和下一条执行地址？

**前置知识：**项目 2；数字逻辑中的寄存器、加法器和控制概念。

**核心内容：**指令集与指令编码；PC、寄存器和内存；取指、译码、执行；数据通路与控制信号的关系。

**实验任务：**用 C 实现 MOV、ADD、LOAD、STORE、JMP、JZ、HALT；明确字长和指令格式；每步输出状态变化；编写求和循环；检查非法指令与越界地址。

**提交成果：**模拟器、指令说明、示例程序与逐步执行轨迹。

**验收标准：**能手工预测短程序的状态序列；解释条件跳转如何形成循环；把 ADD 的执行联系到寄存器读取、运算和写回。

**可选拓展：**增加 CALL 与 RET；画出简化数据通路；之后再考虑流水线。

### 项目 4 链接与装载

多个源文件怎样组成一个程序，名字和地址何时确定？

**前置知识：**项目 0、2；声明、定义和 extern。

**核心内容：**符号表、符号解析与重定位；代码和数据所在的节；静态库与共享库；可执行文件映射与动态链接的基本分工。

**实验任务：**构建跨文件调用与共享变量示例；查看目标文件符号；分别制造未定义引用和重复定义；修复错误；比较使用静态库与共享库的程序。

**提交成果：**多文件项目、符号表观察结果和两种链接错误的分析。

**验收标准：**能区分编译错误与链接错误；解释目标文件为什么仍需重定位；说明链接时确定的内容与装载后仍需处理的内容。

**可选拓展：**在同一环境下更换共享库，观察依赖与装载行为。

### 项目 5 程序优化与 Cache

相同算法复杂度的程序，为什么仍可能有明显性能差异？

**前置知识：**项目 1、2；数组与循环。

**核心内容：**时间与空间局部性、缓存行；内存层次；指令依赖、循环展开与向量化；编译优化；测量误差与瓶颈。

**实验任务：**比较数组连续访问与跨步访问、矩阵按行与按列访问；改变数据规模；比较单累加器和多累加器；检查汇编并重复计时，确保计算结果被使用。

**提交成果：**含环境、编译选项、输入规模、重复测量结果和解释的性能报告。

**验收标准：**能说明测量如何控制变量；区分观察结果与原因假设；不能仅凭耗时差异断定 cache 未命中。计数器不可用时，明确证据限制。

**可选拓展：**实现分块矩阵操作或简化缓存模拟器；条件允许时使用性能计数器。

### 项目 6 进程与异常控制流

程序怎样启动其他程序，操作系统又怎样改变执行流程？

**前置知识：**项目 4；基本字符串处理。

**核心内容：**进程、PID、父子关系；fork、exec、wait；退出状态与僵尸进程；异常、中断、系统调用与信号；调度的基本观念。

**实验任务：**实现前台极简 Shell，支持命令参数、子进程创建和回收；检查命令不存在等失败情况；观察终端中断的效果；用独立实验理解信号和进程终止。

**提交成果：**Shell、进程生命周期记录与错误处理用例。

**验收标准：**解释 fork 为什么有两条返回路径，exec 为什么通常不返回；能说明何时回收子进程；能区分同步异常与异步事件。

**可选拓展：**增加重定向和管道；后台作业及完整作业控制留作进阶任务。

### 项目 7 虚拟内存与动态分配

程序中的地址代表什么，动态内存怎样分配和回收？

**前置知识：**项目 1、2、6；指针与对象生命周期。

**核心内容：**虚拟地址、页、页表、TLB、权限与缺页异常；映射、按需分配与写时复制；堆、栈与动态分配器。

**实验任务：**观察不同对象地址并结合进程映射解释；用模拟页表完成地址翻译；比较分配后未访问与逐页访问的现象；在固定缓冲区中实现带对齐、切分和合并的分配器。

**提交成果：**地址空间观察记录、地址翻译小实验与简单分配器。

**验收标准：**知道地址打印不能单独证明翻译机制；能区分正常缺页与非法访问；检查分配块不重叠、对齐与合并，并解释泄漏、悬空指针和碎片。

**可选拓展：**使用 mmap 管理区域；比较分配策略；观察写时复制。

### 项目 8 文件与系统 I O

程序怎样通过操作系统读写文件，数据在哪些缓冲区中流动？

**前置知识：**项目 6；缓冲区与指针。

**核心内容：**文件描述符、打开文件与偏移；open、read、write、close；短读写、EOF、错误返回与中断；标准 I/O 缓冲。

**实验任务：**实现文件复制工具；循环处理部分写入并检查返回值；比较缓冲区大小；观察标准 I/O 与系统调用的关系；测试空文件、二进制文件、文件不存在和写入失败。

**提交成果：**复制工具、内容一致性检查与系统调用观察记录。

**验收标准：**能解释返回值而非只记住函数名；区分 EOF 与失败；说明谁关闭文件、何时释放缓冲区，并给出失败路径的资源处理。

**可选拓展：**实现带 I/O 重定向的 Shell；检查描述符继承。

### 项目 9 Socket 与 HTTP

一次客户端请求怎样到达程序，并得到完整响应？

**前置知识：**项目 8；文件描述符与错误处理。

**核心内容：**地址与端口、连接与监听 socket；TCP 字节流；阻塞 I/O；HTTP 请求和响应的基本格式。

**实验任务：**先实现回显服务，再实现 HTTP 响应；使用 curl 验证；增加静态文件与 404；处理请求分段到达、长度上限和部分发送；限制文件路径在指定目录内。

**提交成果：**顺序服务器、请求响应记录和受支持的 HTTP 子集说明。

**验收标准：**能跟踪一次请求中的 socket、缓冲区、文件与资源释放；知道 TCP 不保证一次发送对应一次接收；能区分 HTTP 格式错误和传输失败。

**可选拓展：**增加请求日志、超时策略与简单客户端。

### 项目 10 并发与同步

多个请求同时执行时，哪些状态共享，怎样保持正确？

**前置知识：**项目 6、9；资源生命周期。

**核心内容：**进程与线程；共享内存、数据竞争与临界区；互斥锁、条件变量和原子操作；死锁、工作队列与并发模型。

**实验任务：**比较顺序、每连接子进程和多线程版本；用独立计数实验观察同步需求；实现有界工作队列和固定线程池；测试多个客户端、断连和队列满的情况。

**提交成果：**并发服务器、同步设计说明和多客户端验证记录。

**验收标准：**列出共享对象及保护方式；解释复合操作为何不自动原子化；知道普通共享变量的数据竞争在 C 中属于未定义行为；检查退出与释放逻辑。

**可选拓展：**用 I/O 多路复用实现另一版本，比较模型适用条件。

## 综合项目 Mini Linux Web Server

综合项目在项目 9、10 的服务器基础上完善。它汇合链接、进程、动态内存、文件 I/O、网络和并发；数据表示、CPU 模拟与 Cache 实验仍保留为独立成果。

### 功能范围

实现 HTTP/1.0 风格的有限子集：只支持 GET，每连接处理一次请求后关闭；返回固定文本或指定目录中的静态文件；为缺失文件、非法路径和过长请求提供明确响应。采用固定线程池处理并发请求，并记录请求结果。

请求解析必须能够处理分段输入，响应包含准确的长度信息，并循环处理部分发送。明确连接、文件描述符、请求缓冲区和队列元素的所有权；出错、断连和正常退出时均应释放资源。

### 观察与验证

| **工具或方法**  | **需要解释的证据**                     |
|-----------------|----------------------------------------|
| gdb             | 一次请求中的调用栈、寄存器与关键缓冲区 |
| objdump         | 一个关键函数的机器级实现               |
| strace          | 接收、读文件、发送和关闭连接的系统调用 |
| /proc           | 进程、线程、映射与打开的文件描述符     |
| 重复测量        | 不同并发量下的吞吐、耗时和失败情况     |
| 性能计数器 可选 | 在工具和权限允许时补充 CPU 或缓存证据  |

### 最终交付与验收

提交源码、可复现的构建和运行说明、功能验证记录、性能记录以及一次请求的完整解释。说明支持的协议范围和已知限制。至少验证空文件、较大文件、文件缺失、非法路径、请求分段、客户端断连和多客户端并发。

验收时能沿一次 curl 请求说明：数据经过哪些缓冲区，何时进入内核，哪些操作可能阻塞，线程共享什么，以及谁负责释放每项资源。随后修改一个条件，例如增加并发量或减小发送块，先预测变化，再验证预测。

## 学习方法与推进安排

### 每次实验的工作流程

**提出问题：**选择一个可观察的问题，例如改变矩阵访问顺序是否改变耗时。

**写出预测：**记录预计结果、依据和适用条件，不提前用运行结果替代预测。

**构造最小实验：**只保留回答问题所需的代码；检查输入、编译选项和正确性。

**收集证据：**选择能观察对应层次的工具，保存关键输出和环境信息。

**解释与复测：**把观察和推断分别写清楚；有疑问时改变一个条件再次验证。

**检查迁移：**换一个输入或程序，尝试独立预测和解释。

### 教材与 AI 的使用

开始项目时先读必要概念，遇到无法解释的现象再回到教材补足原理。项目结束后整理一页知识结构，并完成少量相关习题，检查实验经验是否已形成通用理解。

可以用 AI 解释术语、审查实验设计和定位错误。每个核心实验仍应自行写出预测、读懂关键代码，并能够在改变输入或删去一部分实现后独立修复。若只能运行生成的代码，应回退到更小的实验。
