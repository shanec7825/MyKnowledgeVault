# 自学文档 7：项目 7——虚拟内存与动态分配

> [!abstract] 中心问题
> C 程序打印出来的地址究竟是什么？为什么每个进程都像拥有一整片独立内存？malloc 又怎样在这片地址空间里管理动态对象？

> [!info] 项目目标
> 本项目分成两半：虚拟内存观察（地址空间、页、映射、权限、缺页、写时复制）与动态分配器实验（在固定缓冲区上实现简单 malloc/free）。不要求实现真实操作系统页表，也不要求替换 glibc malloc。

## 最终成果

- 一份进程地址空间观察记录；
- 一个简化页表翻译程序；
- malloc 后“分配”和“实际触碰页面”的对照实验；
- mmap 与 /proc/<pid>/maps 观察；
- AddressSanitizer 动态内存错误实验；
- 一个支持 alignment、split、coalesce 的教学分配器。

# 第 1 章 指针值通常是虚拟地址

~~~c
#include <stdio.h>
#include <stdlib.h>

int global = 1;

int main(void) {
    int local = 2;
    int *heap = malloc(sizeof(int));

    printf("&main   = %p\n", (void *)main);
    printf("&global = %p\n", (void *)&global);
    printf("&local  = %p\n", (void *)&local);
    printf("heap    = %p\n", (void *)heap);

    free(heap);
}
~~~

这些通常是**进程虚拟地址**，不要把某个 0x7fff... 数值直接称为 RAM 的真实物理位置。

更准确的链路：

~~~text
程序产生虚拟地址
↓
CPU 地址转换机制
↓
TLB / 页表
↓
某个物理页，或当前尚未建立/允许该映射
~~~

# 第 2 章 地址空间区域

典型 Linux 进程可以粗略画成：

~~~text
低地址
┌──────────────────┐
│ executable code  │
│ rodata           │
│ data / bss       │
├──────────────────┤
│ heap             │
│ mmap regions     │
│ shared libraries │
│ ...              │
│ stack            │
└──────────────────┘
高地址
~~~

这是概念图，不保证实际地址或顺序完全相同。

让程序 sleep 60 秒，再：

~~~bash
cat /proc/<PID>/maps
~~~

寻找：

- 主程序；
- libc；
- heap；
- stack；
- 动态链接器。

权限：

~~~text
r  readable
w  writable
x  executable
p  private
s  shared
~~~

把程序打印出的 main/global/local/heap 地址分别定位到 maps 区间。

# 第 3 章 页与地址拆分

查看页大小：

~~~bash
getconf PAGESIZE
~~~

常见为 4096 字节，也就是 2^12。

因此可把虚拟地址想成：

~~~text
virtual page number | page offset
                     低 12 位
~~~

若地址为：

~~~text
0x7f12abcd3456
~~~

在 4 KiB 页下：

~~~text
offset = address & 0xfff
VPN    = address >> 12
~~~

自己写程序打印至少 3 个地址的 VPN 与 offset。

# 第 4 章 简化页表模拟器

为了把“翻译”变成可操作算法，定义：

~~~text
虚拟地址：16 位
页大小：256 B = 2^8
VPN：高 8 位
offset：低 8 位
~~~

例如：

~~~text
VA = 0x1234
VPN = 0x12
offset = 0x34
~~~

若页表：

~~~text
VPN 0x12 → PPN 0xA7
~~~

则：

~~~text
PA = 0xA734
~~~

代码骨架：

~~~c
typedef struct {
    int valid;
    unsigned ppn;
    int writable;
} PTE;

PTE page_table[256];

int translate(uint16_t va, int write, uint16_t *pa) {
    unsigned vpn = va >> 8;
    unsigned off = va & 0xff;
    PTE pte = page_table[vpn];

    if (!pte.valid)
        return -1;

    if (write && !pte.writable)
        return -2;

    *pa = (uint16_t)((pte.ppn << 8) | off);
    return 0;
}
~~~

测试：

- 合法读；
- 合法写；
- 只读页写入；
- invalid page。

# 第 5 章 TLB：缓存“翻译”

如果每次 load/store 都完整走页表，代价很高。

TLB 的概念：

~~~text
虚拟地址
↓
TLB lookup
├─ hit → 直接得到物理页号
└─ miss → page table walk → 再填入 TLB
~~~

区分：

~~~text
Cache：缓存数据/指令
TLB：缓存虚拟页到物理页的翻译
~~~

# 第 6 章 Page Fault 不等于程序崩溃

page fault 的准确理解：

> 当前内存访问需要内核介入，CPU 不能直接完成。

可能是：

- 首次访问按需分配页面；
- 文件映射首次访问；
- copy-on-write；
- 页面暂不在内存；
- 权限非法。

因此：

~~~text
page fault ≠ segmentation fault
~~~

后者通常是内核最终判断访问不合法并向进程发送信号后的结果。

# 第 7 章 malloc 后“拿到地址”不等于所有物理内存已实际使用

实验：

~~~c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(void) {
    size_t n = 512UL * 1024 * 1024;
    char *p = malloc(n);

    if (!p) {
        perror("malloc");
        return 1;
    }

    printf("allocated at %p\n", (void *)p);
    sleep(20);

    for (size_t i = 0; i < n; i += 4096)
        p[i] = 1;

    puts("touched");
    sleep(20);

    free(p);
}
~~~

另一终端：

~~~bash
ps -o pid,rss,vsz,cmd -p <PID>
grep -E 'VmSize|VmRSS' /proc/<PID>/status
~~~

比较：

~~~text
刚 malloc
逐页写入之后
~~~

典型情况下，虚拟地址空间增长与实际驻留物理内存增长并不同步。

> [!warning]
> malloc 实现、Linux overcommit、内核版本都会影响数字。保留环境，不把一次测量当普遍常数。

# 第 8 章 mmap

匿名映射：

~~~c
#include <sys/mman.h>

void *p = mmap(
    NULL,
    4096,
    PROT_READ | PROT_WRITE,
    MAP_PRIVATE | MAP_ANONYMOUS,
    -1,
    0
);

if (p == MAP_FAILED) {
    perror("mmap");
}
~~~

释放：

~~~c
munmap(p, 4096);
~~~

然后在 /proc/PID/maps 中找到新映射。

## 8.1 文件映射

~~~c
int fd = open("data.bin", O_RDONLY);

void *p = mmap(
    NULL,
    length,
    PROT_READ,
    MAP_PRIVATE,
    fd,
    0
);
~~~

之后对 p 的内存读取可以对应文件中的内容。

这建立一条重要联系：

~~~text
文件
↔
虚拟内存映射
↔
页面
~~~

# 第 9 章 fork 与 Copy-on-Write

项目 6 已看到：fork 后父子变量互不影响。

如果 fork 立即复制所有物理页，代价很大。常见机制是：

~~~text
fork
↓
父子暂时共享物理页
↓
相关页受到写保护
↓
某一方第一次写
↓
产生异常
↓
内核复制那一页
↓
父子获得独立副本
~~~

实验可用大数组：

~~~c
size_t n = 128UL * 1024 * 1024;
char *p = malloc(n);
memset(p, 1, n);

pid_t pid = fork();

if (pid == 0) {
    sleep(10);

    for (size_t i = 0; i < n; i += 4096)
        p[i]++;

    sleep(20);
    _exit(0);
}
~~~

观察父子 /proc/PID/status。

这里只要求把观察与 COW 模型对应，不要求从 RSS 精确反推出内核页表细节。

# 第 10 章 页面权限

从 maps 中观察 r-x、rw- 等权限。

可以在**自己创建的匿名页**上实验：

~~~c
void *p = mmap(
    NULL, 4096,
    PROT_READ | PROT_WRITE,
    MAP_PRIVATE | MAP_ANONYMOUS,
    -1, 0
);

if (p == MAP_FAILED)
    return 1;

((char *)p)[0] = 'A';

if (mprotect(p, 4096, PROT_READ) == -1)
    perror("mprotect");
~~~

把页改为只读以后，再写会让这个独立测试进程发生非法访问。

实验目的：

> 看到“地址存在”和“当前操作有权限”是两件事。

# 第 11 章 malloc/free 的对象生命周期

~~~c
void *p = malloc(n);
~~~

成功后：

- 获得至少 n 字节可用区域；
- 返回地址具有合适对齐；
- 内容不是自动初始化为 0；
- 使用结束要 free。

~~~c
free(p);
~~~

free 之后，变量 p 可能还保存旧数值，但那块对象的生命周期已结束。

# 第 13 章 教学分配器：在固定缓冲区上模拟 heap

~~~c
#define HEAP_SIZE 4096

static unsigned char heap[HEAP_SIZE];
~~~

块：

~~~text
[ header ][ payload ][ header ][ payload ] ...
~~~

header：

~~~c
typedef struct block {
    size_t size;
    int free;
    struct block *next;
} block_t;
~~~

这不是 glibc malloc 的真实实现，而是理解分配器最小机制的模型。

# 第 14 章 初始化

~~~c
static block_t *first_block;

void allocator_init(void) {
    first_block = (block_t *)heap;
    first_block->size = HEAP_SIZE - sizeof(block_t);
    first_block->free = 1;
    first_block->next = NULL;
}
~~~

# 第 15 章 Alignment

# 第 16 章 First Fit

逻辑：

~~~text
从 first_block 开始
↓
找第一个 free && size >= need
↓
必要时 split
↓
标记 free=0
↓
返回 payload 起点
~~~

骨架：

~~~c
void *my_malloc(size_t n) {
    if (n == 0)
        return NULL;

    n = align8(n);

    for (block_t *cur = first_block; cur; cur = cur->next) {
        if (cur->free && cur->size >= n) {
            // split if useful
            cur->free = 0;
            return (unsigned char *)cur + sizeof(block_t);
        }
    }

    return NULL;
}
~~~

# 第 17 章 Split

若空闲块 200 字节，请求 64：

~~~text
之前：
[header | free 200]

之后：
[header | used 64][header | free remaining]
~~~

只有剩余空间足够容纳：

~~~text
新 header + 至少一个有意义的 payload
~~~

才值得 split。

计算新块位置时必须使用**字节指针**，避免错误的结构体指针算术。

# 第 18 章 Free 与 Coalesce

my_free：

~~~text
payload pointer
↓
退回 sizeof(header)
↓
得到 block header
↓
标记 free
↓
尝试合并相邻 free block
~~~

相邻：

~~~text
[A free][B free]
~~~

合并：

~~~text
[A larger free]
~~~

更新 A.size 与 A.next。

# 第 19 章 碎片

## Internal Fragmentation

请求 13，按对齐给 16，内部浪费 3。

## External Fragmentation

~~~text
free20 | used | free20 | used | free20
~~~

总空闲 60，但连续最大块只有 20，因此请求 40 仍可能失败。

split 能提高空间利用，coalesce 能缓解外部碎片。

# 第 20 章 分配器不变量

实现：

~~~c
int allocator_check(void);
~~~

至少检查：

1. block header 位于 heap 内；
2. 每个 block 的结尾不越过 heap；
3. block 不重叠；
4. payload 按设计对齐；
5. next 按地址前进；
6. 链表无环；
7. allocated 块不会重复返回；
8. 合并策略开启时不应保留相邻 free 块。

这比单纯“程序没崩”更能证明分配器正确。

# 第 21 章 Heap 可视化

~~~c
void allocator_dump(void) {
    for (block_t *cur = first_block; cur; cur = cur->next) {
        ptrdiff_t off = (unsigned char *)cur - heap;
        printf("offset=%td size=%zu free=%d\n",
               off, cur->size, cur->free);
    }
}
~~~

每次 alloc/free 后打印，画出块变化。
