# 项目 0 命令速查卡

> [!tip] 怎么用
> 这是**查阅用**的卡片，不用背。忘记某个选项时，Ctrl+F 搜关键词（比如"反汇编"、"调试信息"）或按命令名搜（比如"objdump"、"gcc"）。

---

## 1. gcc：四步流水线 + 调试编译

| **你要做的事** | **命令** | **选项含义** | **产物** |
| --- | --- | --- | --- |
| 预处理（展开 #include、宏） | `gcc -E main.c -o main.i` | `-E` = only **E**xpand | main.i（纯文本） |
| 编译到汇编 | `gcc -S main.c -o main.s` | `-S` = **S**ource/assembly | main.s（汇编文本） |
| 汇编到目标文件 | `gcc -c main.c -o main.o` | `-c` = **c**ompile only | main.o（ELF relocatable） |
| 链接成可执行 | `gcc main.c -o a.out` | 无选项 = 走完四步 | a.out（ELF executable） |
| **调试编译（必背）** | `gcc -g -O0 main.c -o a.out` | `-g` = debug info；`-O0` = 优化 0 级 | a.out（可调） |
| 优化编译（做对比） | `gcc -g -O2 main.c -o a_O2` | `-O2` = 高优化 | a_O2（更快但变量可能被优化掉） |

> [!warning] 编译观察结论时必须注明条件
> 观察变量时必须用 `-g -O0`；如果用 `-O2`，变量会变成 `<optimized out>`，结论不成立。

## 2. objdump：看磁盘上的二进制

| **你要做的事** | **命令** | **选项含义** | **看到什么** |
| --- | --- | --- | --- |
| 看符号表（地址是 0 还是真实地址） | `objdump -t main.o` | `-t` = symbol **t**able | add / main 函数名 + 地址 |
| 看反汇编（机器码→汇编） | `objdump -d a.out` | `-d` = **d**isassemble | `<add>:` 函数体、call 指令 |
| 看节头（代码/数据分布） | `objdump -h a.out` | `-h` = **h**eader | .text / .data 各在哪个地址段 |

> [!tip] 记住三个就够了
> `-t` = 看符号，`-d` = 看反汇编，`-h` = 看节头。其他选项用到再 `objdump --help | grep xxx`。

### 常用组合拳

```bash
objdump -t main.o | grep -E " add| main"       # 只看 add 和 main 的符号
objdump -d a.out | grep -A 20 "<add>:"          # 看 add 的反汇编
objdump -d a.out | grep "call"                  # 找所有 call 指令
```

## 3. gdb：看运行中的进程

| **命令** | **选项含义** | **场景** |
| --- | --- | --- |
| `gdb ./a.out` | 启动调试 | 必须用 `-g` 编译过 |
| `break add` | 断点（按函数名） | 停在 add 入口（函数体第一条语句） |
| `break main.c:9` | 断点（按文件:行号） | 停在调用行的行首（还没执行） |
| `run` | 运行到断点 | 按下播放键 |
| `next` / `n` | 执行下一行，**不进**函数 | 单步跨过 |
| `step` / `s` | 执行下一行，**进**函数 | 单步跨入 |
| `print x` / `p x` | 打印变量/表达式 | 伸手量一量 |
| `info args` | 看当前函数的参数 | a=3 b=4 |
| `info locals` | 看局部变量 | |
| `info registers rdi rsi rax` | 看寄存器 | |
| `backtrace` / `bt` | 看调用栈 | 谁调用了 add？ |
| `frame 1` / `up` | 切到上一层栈帧 | 在 add 里看 main 的变量 |
| `continue` / `c` | 继续跑到下一个断点 | |
| `quit` / `q` | 退出 gdb | |

> [!question] 符号断点 vs 行断点
> `break add` = 符号断点 → 停在 add 入口（此时 call **已经**执行完）。
> `break main.c:9` = 行断点 → 停在第 9 行行首（此时 call **还没**执行，参数还没进 rdi/rsi）。
> 要观察"main 怎么把参数交给 add"，必须用**行断点**。

## 4. file：看文件类型

| **命令** | **看到什么** |
| --- | --- |
| `file main.c` | C source, ASCII text |
| `file main.o` | ELF 64-bit relocatable（目标文件，地址未定） |
| `file a.out` | ELF 64-bit pie executable（可执行，已定地址） |
| `file a.out` | 若显示 `with debug_info` → 用了 `-g` 编译 |

## 5. strace：看系统调用

| **命令** | **选项含义** | **场景** |
| --- | --- | --- |
| `strace ./a.out` | 跟踪系统调用 | 看 write / execve / exit_group |
| `strace -c ./a.out` | 汇总统计 | 每种调用出现了几次、耗时占比 |
| `strace -e write ./a.out` | 只看 write | 过滤特定调用 |
| `strace -f ./a.out` | 跟踪子进程 | 项目 6 用 |

## 6. 命令行基础（日常操作）

| **你要做的事** | **命令** | **选项含义** |
| --- | --- | --- |
| 看文件内容 | `cat main.c` | 全文打印 |
| 看文件前 5 行 | `head -n 5 main.i` | 前 n 行 |
| 看文件最后 10 行 | `tail main.s` | 后 10 行 |
| 看文件行数 | `wc -l main.c` | **w**ord **c**ount - **l**ine |
| 分页查看 | `less main.s` | 按 q 退出 |
| 查找文本 | `grep "add" main.c` | 搜索匹配行 |
| 带行号查 | `grep -n "add" main.c` | 显示行号 |
| 递归查目录 | `grep -r "add" .` | 当前目录下所有文件 |
| 保存输出 | `objdump -d a.out > asm.txt` | 标准输出重定向 |
| 保存输出+报错 | `strace ./a.out > log.txt 2>&1` | `2>&1` 连 stderr 一起存 |
| 追加输出 | `echo "text" >> log.txt` | `>>` 追加，`>` 覆盖 |
| 看文件类型 | `file a.out` | |
| 列目录 | `ls -l` | 长格式（权限/大小/时间） |
| 权限 | `chmod +x a.out` | 加执行权限 |
| 看进程 | `ps -ef \| grep a.out` | 过滤后找 PID |
| 进程详情 | `cat /proc/<PID>/status` | 内核的进程档案 |

## 7. 选项命名规律（帮你猜 + 猜后验证）

| **规律** | **例子** | **说明** |
| --- | --- | --- |
| 全称首字母 | `-c` = compile, `-S` = Source, `-d` = disassemble | 常见规律 |
| 不是首字母 | `-t` = symbol table, `-g` = debug info (GNU) | 靠反复用 |
| 优化级别 | `-O0`, `-O1`, `-O2` | O 是大写，不是 0 |
| 长选项 | `--version`, `--help`, `--no-pie` | 两个减号 + 全称 |
| 同字母不同含义 | `file -d` = directory, `objdump -d` = disassemble | **别猜，查 help** |

> [!warning] 不要猜选项
> 猜错了浪费时间，`objdump --help | grep xxx` 才是最快的路。

## 8. 高频套路（可直接抄）

### 一键调试存证

```bash
gdb -q -batch -ex "set pagination off" -ex "set debuginfod enabled off" \
    -ex "break main.c:9" -ex run -ex "print x" -ex "print y" \
    -ex "info registers rdi rsi" -ex "disassemble main" \
    -ex step -ex "info args" -ex "info registers rdi rsi" \
    -ex next -ex "print \$rax" -ex backtrace \
    ./a.out > 07b-gdb调用点断点.txt 2>&1
```

### 一键反汇编保存

```bash
objdump -d a.out > asm.txt
grep -n "<add>:" asm.txt
grep -n "call" asm.txt
```

### 一键系统调用轨迹

```bash
strace ./a.out > trace.txt 2>&1
grep "write\|execve\|exit" trace.txt
```

## 9. 容易混淆的概念

| **A** | **B** | **区别** |
| --- | --- | --- |
| `gcc -c` | `gcc`（无选项） | -c 只到目标文件；无选项走完链接 |
| `next` | `step` | next 不进函数；step 进函数内部 |
| `break add` | `break main.c:9` | 符号断点 vs 行断点 |
| `> log.txt` | `>> log.txt` | > 覆盖；>> 追加 |
| `.o` (目标文件) | `a.out` (可执行) | .o 地址未定、不能运行；a.out 已定、可运行 |
| `info args` | `info locals` | args 是参数（a、b）；locals 是局部变量（x、y） |
| `rdi/rsi` | `rax` | rdi/rsi 放参数（进）；rax 放返回值（出） |

> [!abstract] 一页速记
> ```bash
> 编译四步：-E 预处理 → -S 编译 → -c 汇编 → 无选项 链接
> 调试编译：gcc -g -O0
> objdump：-t 看符号 | -d 看反汇编 | -h 看节头
> gdb：break 断点 | run 运行 | next/step 单步 | info 查看 | bt 调用栈 | c 继续
> 断点：break add = 入口断点 | break main.c:9 = 调用行断点
> strace：-c 汇总 | -e 过滤 | -f 跟子进程
> 不记得就 objdump --help | grep xxx
> ```
