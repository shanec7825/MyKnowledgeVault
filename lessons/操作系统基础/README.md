## 这门课究竟学什么？

**一条主线：** C 代码怎样变成可执行文件，在 CPU、内存和操作系统的协作下运行，最后通过文件或网络与外界交互。

## 先写代码，再看解释：四步小循环

1. **先猜**：用一句话写下预计输出，必要时手算寄存器 / 地址 / 位值。
2. **亲手改源码**：在网页的「源代码」编辑器中修改一处关键语句，不是只点击观看动画。
3. **去真实 Ubuntu 运行**：复制「终端命令」，在 WSL 的 Ubuntu 或 VS Code 的 Ubuntu 终端亲自执行。网页离线，**无法直接运行 C、GCC 或 HTTP 服务**。
4. **收集证据再解释**：把终端 stdout 或报错粘贴回网页「对照观察」；页面只会对照原示例的特征，**不会伪装成已经执行、不会给你的代码自动判分**。然后再看下方的可视化实验、教材与变式练习。

先用两条终端命令确认自己在哪儿：

```bash
pwd
gcc --version
```

如果还不熟悉终端，参考 [[自学文档0（补）-WSL 实操衔接手册]]。**不要为记住工具名而重复整个 GCC/GDB 教程**；当需要观察汇编、调试或链接错误时再补查。

| 你现在的程度 | 只做这些就行 |
| --- | --- |
| 第一次接触 | 修改一行代码，复制命令，看到输出 |
| 已经做过一次 | 不看答案先预测，自己解释修改引起的变化 |
| 想再深入 | 用 gdb / objdump / strace / 教材验证更深层机制 |

页面的「已探索」只代表操作过教学模拟。代码草稿保存在本地浏览器，贴入的终端输出不会上传；真正独立掌握仍由你自己的代码与 Ubuntu 记录支持。
