# 微实验 03：三条指令的小CPU

> [!success] 今天的最小目标
> CPU 不一定神秘。先把它想成按顺序读指令、改变寄存器的小机器。 不必先做原课程的大项目。

## 先预测一个现象

从 0 开始，连续加 3、加 5、再加 -2，每步寄存器 r0 是多少？

## 先看一张机制图

```mermaid
flowchart LR
    P[PC 选择当前指令] --> R[读取加数]
    R --> A[执行加法]
    A --> W[写回 r0]
    W --> N[PC 前进一格]
    N --> P
```

> [!note] 这是简化模型
> 这张图只展示本实验关心的因果顺序，没有把真实系统的全部机制画进来。

## 在 WSL 只做一个实验

```bash
mkdir -p ~/cs-system/tiny3 && cd ~/cs-system/tiny3
cat > demo.c <<'EOF'
#include <stdio.h>
int main(void) {
    int r0 = 0, program[] = {3, 5, -2};
    for (int pc = 0; pc < 3; ++pc) {
        r0 += program[pc];
        printf("pc=%d r0=%d\n", pc, r0);
    }
}
EOF

gcc demo.c -o demo && ./demo
```

**你应该看见：**

```text
pc=0 r0=3
pc=1 r0=8
pc=2 r0=6
```

> [!tip] 小提示
> 如果出现“命令不存在”“文件不存在”，先用 `pwd`、`ls`、`gcc --version` 定位问题；WSL 基础见 [[自学文档0（补）-WSL 实操衔接手册]]。

## 改一个条件，再试

把程序的第二项 5 改成 10，预测第三步的值。

## 现在解释，不必马上记全套概念

这是**教学用 ADD-立即数模型**，不是真实 x86 CPU、也没有实现内存取指、译码与跳转。你先学会“每条指令改变状态”，再尝试完整模拟器。

**自查**：你能不看答案说出“什么东西变了 → 为什么输出变了”吗？能就完成了这个微实验；不能就回去改一次输入。
