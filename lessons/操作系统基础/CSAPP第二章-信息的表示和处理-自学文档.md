# CSAPP 第二章：信息的表示和处理｜自学文档

> 对应《深入理解计算机系统（第3版）》第 2 章。目标不是记公式，而是建立一条主线：**位模式 → 数据类型的解释规则 → 机器运算 → C 程序行为**。

## 0. 学完这一章，你应该能做什么

学完后，你应当能够：
- 看懂一个整数或浮点数在机器中的位级表示；
- 解释大端/小端、字节序、十六进制与内存布局；
- 熟练使用掩码、移位和位运算；
- 在无符号数与补码之间进行转换，并判断类型转换的结果；
- 理解整数加法、乘法为何会溢出，以及机器为什么仍能高效计算；
- 解释 IEEE 754 浮点数的规格化、非规格化、无穷、NaN 与舍入；
- 看到 C 表达式时主动检查“类型、位宽、符号、溢出、舍入”。

## 1. 全章地图

第二章可以看成四层：

1. **信息存储（2.1）**：比特怎样组成字节、对象怎样放入内存。
2. **整数表示（2.2）**：同一串比特怎样被解释为 unsigned 或 two's complement。
3. **整数运算（2.3）**：固定字长下，加减乘除到底在算什么。
4. **浮点数（2.4）**：如何用有限比特近似实数，并处理范围与精度。

核心观念：**内存只保存比特；“它是什么数”取决于解释规则。**

## 2. 2.1 信息存储

### 2.1.1 比特、字节与十六进制

一个字节通常是 8 bit，因此可表示 0~255。二进制适合机器，十六进制适合人观察位模式：1 个十六进制位正好对应 4 bit。

例如：

`0x2D = 0010 1101₂`

训练目标不是反复做进制转换，而是能快速把十六进制当成“压缩后的二进制”阅读。

### 2.1.2 字与地址

机器有“字长”概念。32 位、64 位系统最重要的区别之一，是指针/虚拟地址空间的典型宽度不同。

内存可抽象为一个巨大的**字节数组**，每个字节都有地址。C 中一个对象占若干连续字节，指针保存对象首地址。

### 2.1.3 字节序：大端与小端

多字节对象放进内存时，需要规定最低有效字节和最高有效字节谁放在低地址。

- 小端：最低有效字节在低地址；
- 大端：最高有效字节在低地址。

例如整数 `0x12345678`，若从低地址向高地址观察：

```text
小端：78 56 34 12
大端：12 34 56 78
```

不要把“位的左右顺序”和“字节在内存中的地址顺序”混为一谈。

### 2.1.4 字符串与代码

字符串的字节表示通常更容易跨平台理解，因为字符逐字节排列。机器代码则依赖 ISA、操作系统和编译结果，不应期待不同机器生成相同字节序列。

### 2.1.5 布尔代数与位运算

四个常用操作：

- `&`：按位与，常用于清零/取掩码；
- `|`：按位或，常用于置位；
- `^`：按位异或，常用于翻转不同位；
- `~`：按位取反。

关键区别：`&& || !` 是逻辑运算；`& | ^ ~` 是位级运算。

### 2.1.6 移位

- 左移：低位补 0；
- 逻辑右移：高位补 0；
- 算术右移：通常复制符号位。

对负数右移、超出位宽的移位等情况，写 C 程序时不要仅凭“硬件大概会这样”推理，要区分语言规则与具体机器行为。

### 小实验：看见内存

```c
#include <stdio.h>

int main(void) {
    unsigned x = 0x12345678;
    unsigned char *p = (unsigned char *)&x;
    for (size_t i = 0; i < sizeof(x); ++i)
        printf("%02x ", p[i]);
    puts("");
}
```

预测输出，再在 WSL 中编译运行。你的重点是解释“为什么”。

## 3. 2.2 整数表示

### 3.1 无符号数

w 位无符号数：

`B2U(x) = Σ x_i 2^i`

范围：

`0 ~ 2^w - 1`

本质就是普通二进制权值展开。

### 3.2 补码

w 位补码最高位具有负权：

`B2T(x) = -x_(w-1) 2^(w-1) + Σ x_i 2^i`

范围：

`-2^(w-1) ~ 2^(w-1)-1`

因此补码范围是不对称的：最小负数没有对应的正数。

### 3.3 同一位模式，不同解释

例如 8 位：

`11111111`

- unsigned：255
- two's complement：-1

**比特没有变，解释函数变了。** 这是理解强制类型转换的关键。

### 3.4 有符号与无符号转换

C 中在相同位宽的 signed/unsigned 转换通常保持底层位模式，而改变数值解释。

特别危险的是混合表达式：当 signed 与 unsigned 同时参与运算时，隐式转换可能让负数变成很大的无符号数。

因此看到比较表达式时，先问：

> 两边最终以什么类型参与比较？

### 3.5 扩展与截断

位宽变大：
- unsigned 常用零扩展；
- 补码 signed 常用符号扩展。

位宽变小：高位被截断，数值可能发生巨大变化。

记忆方式不是背规则，而是先保留/删除**位模式**，再按目标类型重新解释。

## 4. 2.3 整数运算

### 4.1 无符号加法 = 模运算

w 位无符号加法本质上：

`(x + y) mod 2^w`

超出 w 位的高位被丢弃，所以“溢出”不是 CPU 算错，而是固定宽度表示的自然结果。

### 4.2 补码加法

补码加法的硬件可以和无符号加法共享同一个加法器；差别主要在于我们如何解释结果，以及如何判断有符号溢出。

有符号加法典型溢出：
- 两个正数相加得到负数；
- 两个负数相加得到非负数。

### 4.3 取负

补码取负可理解为：

`-x = ~x + 1`

但最小补码值是特殊点：它的数学相反数超出可表示范围。

### 4.4 乘法

固定 w 位乘法同样只保留低 w 位。乘以 2 的幂可以与左移联系起来，这也是编译器优化整数乘法的基础之一。

不要形成“移位永远比乘法快，所以我要手工优化”的旧经验；现代编译器通常能完成这类变换。这里学习移位，是为了理解机器算术。

### 4.5 除以 2 的幂

无符号数右移可自然对应除以 2 的幂。补码负数则涉及算术右移与“向零舍入”的修正，因此比表面上复杂。

### 4.6 一个统一模型

整数机器运算最值得掌握的模型：

> **先在无限精度数学中计算 → 只保留 w 位 → 按 signed/unsigned 解释。**

它能统一解释大量“奇怪结果”。

## 5. 2.4 浮点数

### 5.1 为什么整数方案不够

实数既可能非常大，也可能非常接近 0。固定小数点无法同时兼顾巨大范围与有效精度，因此浮点数采用类似科学计数法的结构。

IEEE 754 的核心位域：

`s | exp | frac`

对应思想：

`(-1)^s × M × 2^E`

### 5.2 三类核心编码

#### 规格化数

exp 既非全 0 也非全 1。尾数含隐含的前导 1：

`M = 1 + f`

指数使用偏置编码：

`E = e - Bias`

#### 非规格化数

exp 全 0。用于表示 0 附近非常小的数，并让数值逐渐接近 0。

#### 特殊值

exp 全 1：
- frac = 0：±∞
- frac ≠ 0：NaN

### 5.3 浮点数最重要的不是“范围”，而是“间距”

浮点数不是均匀铺在数轴上的。数值越大，相邻可表示数之间的绝对距离通常越大。

因此：

```text
浮点数 ≠ 实数
浮点运算 ≈ 先做数学运算，再舍入到最近的可表示值
```

这解释了为什么某些十进制小数不能被二进制浮点精确表示。

### 5.4 舍入

常见默认策略是“向偶数舍入”（round to even）。它的意义之一是避免大量恰好位于中点的舍入长期偏向同一方向。

### 5.5 浮点运算的代数性质

浮点加法、乘法可能不满足你在实数中习惯使用的全部代数变形。例如由于中间结果舍入，加法结合律可能失效。

因此数值程序中：

> 数学上等价的表达式，机器上未必产生完全相同的结果。

## 6. 四组最容易混淆的概念

| 容易混淆 | 正确区分 |
|---|---|
| 比特模式 vs 数值 | 位模式是存储内容；类型决定解释 |
| 大端/小端 vs 二进制书写顺序 | 前者讨论字节地址排列 |
| unsigned 溢出 vs 程序错误 | unsigned 按模运算有明确语义，但算法可能因此出错 |
| 浮点“精度高” vs “精确” | 浮点只是有限集合上的近似 |

## 7. 推荐学习顺序

### 第一轮：建立模型
读 2.1 → 2.2，只回答两个问题：
1. 数据如何成为内存中的字节？
2. 同一位模式如何被不同类型解释？

### 第二轮：推导机器算术
读 2.3。所有题尽量使用“模 2^w / 截断 / 重新解释”的统一模型，而不是背各种特例。

### 第三轮：攻克浮点
读 2.4。先画出简化的 8 位浮点格式，再研究 IEEE 754 单精度/双精度，会比直接背 32/64 位字段容易。

### 第四轮：写程序验证
使用 `gcc`、`gdb`、`sizeof`、指针和十六进制输出，把预测与真实机器结果对照。

## 8. 本章实验路线

### 实验 A：Endian Explorer
输入一个 `uint32_t`，逐字节打印其内存表示。

### 实验 B：Bit Inspector
实现函数打印任意整数的二进制表示，并尝试掩码、置位、清位、翻转。

### 实验 C：Signed/Unsigned Trap
构造 signed/unsigned 混合比较，先手算转换，再运行验证。

### 实验 D：Overflow Lab
用较小位宽手算无符号与补码加法，观察截断；再用 C 验证边界。

### 实验 E：Mini Float
自己设计一个 8 位浮点格式，例如 1 位符号 + 4 位指数 + 3 位小数，枚举全部 256 个位模式并画到数轴上。

完成 E 后，IEEE 754 会从“规则表”变成可以直观看见的结构。

## 10. 与后续课程的连接

第二章不是孤立的“进制转换章”。

- 到机器级程序：寄存器里的数据仍是这些位模式；
- 到链接与装载：地址、字节布局会继续出现；
- 到 Cache：内存地址会被拆成 tag/index/offset；
- 到虚拟内存：地址本身又成为需要解释和转换的位串；
- 到安全：整数溢出、类型转换、边界错误可能演化为漏洞。

所以本章真正建立的是整个计算机系统课程的**数据观**：

> **系统的底层对象最终都是有限位宽的比特串；理解系统，就是理解这些比特如何被存储、解释、变换和传递。**
