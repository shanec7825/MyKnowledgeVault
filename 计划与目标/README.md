# 学习计划与目标｜使用说明

**目标**：从“学过什么”的模糊记忆，转为可检查的 **目标 → 阶段 → 任务 → 验收 → 复习 → 再计划**。这是一个独立的 Obsidian Markdown 体系，不依赖新插件；已安装的 Dataview 用于自动查询，Templater 可用于创建模板。

## 入口
- [[计划与目标/00-学习总览|学习总览（每天先打开）]]
- [[计划与目标/03-每日计划/2026-10-09|首个建议日计划：2026-10-09]]
- [[计划与目标/04-每周复盘/2026-W41|本周复盘草稿]]
- 课程：见 `01-课程目标/`，独立任务：见 `02-学习任务/`，模板：见 `05-模板/`。

## 一项任务的三类事实（务必分清）
1. **资料事实**：课程文档、HTML、学习包已经存在。不能推出你已完成。
2. **讨论事实**：曾向 AI 提问、讲述某个解题思路。说明接触或尝试过，不保证脱离提示能做。
3. **验收事实**：你亲自交出代码、题目推导、实验结果、写作或表达，并在新的输入下能解释。只有这种证据才计入“已验收”。

**ChatGPT 左侧 Projects 并不能在此处自动批量导入**。初始资料使用现有知识库和能找到的历史讨论；其余项目需手工补足或以后再导入。不要把 AI 的建议当成你的完成记录。

## 元数据统一规范
- 课程：`type: course-goal`、`phase`、`status: active|paused`。
- 任务：`type: learning-task`、`course`、`stage`。
- `status`：`todo` 未执行；`doing` 正在跟进；`blocked` 受阻；`done` 验收通过；`paused` 暂缓。
- `verified`：只有有独立证据才设为 `true`，且与 `status: done` 配套。
- `mastery`：`null` 未测；0 无法解释；1 看提示能解释；2 独立做出；3 能迁移。
- `scheduled`：计划执行日；`review_due`：下一检查/复习日；`review_kind`：`none|diagnostic|spaced`；`review_step`：已完成第几个间隔阶段。
- 所有初始任务的 `verified: false`，这是有意设置的，不要因文件存在而改成 true。

## 每日最小操作
1. 打开 [[计划与目标/00-学习总览]]，查看待办与到期复习。
2. 选择 **1 个主任务 + 1 个次任务 + 少量日常练习**，不要直接把全部课程塞进当天。
3. 从模板创建日计划，链接到原始任务而非复制任务全文。
4. 当天结束只记录“做了什么/证据在哪/卡点是什么/下次何时提取”，而不是仅记录时长。
5. 每周查 [[计划与目标/04-每周复盘/2026-W41]] 一次，调整任务优先级和阶段。

## 间隔复习规则
- 首次通过验收后可设 `review_kind: spaced`、`review_step: 0`，下一次复习日设为完成日 +1 天。
- 后续成功复习按 +3、+7、+14、+30 天调整；失败则适当提前重测并在记录里说明。
- 初始 `diagnostic` 任务是对已讨论知识的**检测**，不是证明以前已经掌握。
- **Dataview 负责查询，不会自动写入或计算下一次复习日期。** 后续真有需要，再利用现有 Templater 或添加小型调度脚本。

## 仓库约定
- 不修改原有 `lessons/`、`EnglishLearning/`、`MusicLearning/` 等课程资料。
- 永远保留原始证据链接与自身反思；AI 能协助解释、评估、规划，但不能替代你的独立验收。
- 内容与格式优先兼容 Obsidian 原生 Markdown、YAML frontmatter、内部链接和 Dataview。
